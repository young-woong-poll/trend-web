## 한 줄 요약

핫픽의 콘텐츠 산발 문제(연애·결혼·정치·경제 등 7개 카테고리 분산)를 해결하기 위해, **카테고리를 "소개팅" 단일로 좁히고**, 페르소나 "민지(26세 직장인 여성)"의 통념 검증 갈증을 메인 JTBD로 잡아, **릴스·쇼츠·X·스레드·커뮤니티에 통념형 영상·카드를 6주간 집중 배포**해 1회 이상 투표 참여 순수 유저 100명을 모은다. 운영 DB의 기존 카테고리·카드 매핑은 **건드리지 않고**, 신규 `dating` 슬러그만 추가한 뒤 FE 화이트리스트(`['dating']`)로 노출 카테고리를 통제한다. 기존 카드 중 소개팅 핏인 것은 사용자가 어드민에서 수동으로 `dating` 카테고리를 추가한다. 화이트리스트 한 줄 변경만으로 전 상태로 즉시 복귀 가능한 완전 2-way door 구조.

## 배경

- 현재 핫픽 메인은 7개 카테고리(연애 / 결혼 / 관계 / 재테크 / 직장 / 라이프 / 트렌드)로 산발돼 있음. 신규 진입자에게 "핫픽이 무엇을 위한 도구인지" 한 줄로 안 잡힘.
- 웅일이 할머니 콘텐츠 약 10여 편으로 릴스·쇼츠 합산 수만 조회수 + 팔로워 급증 검증. 멀티 플랫폼 + 후킹 콘텐츠 공식이 작동함을 확인.
- 핫픽 마케팅을 같은 공식으로 가져가려면, **콘텐츠 주제 자체가 좁아야** 영상·카드 후킹이 명료해진다. 7개 카테고리로 산발하면 영상 1편당 후킹 코어가 흐려짐.
- 후보 카테고리 4개(소개팅 / 민폐 / 인간관계 / 연애) 중 **소개팅**이 (a) 20-30대 바이럴성 최강, (b) "답 없는 논쟁" 본질에 가장 맞음, (c) 남녀노소 즉시 공감, (d) 민폐는 검증 부족, 연애·인간관계는 너무 포괄적 — 이유로 단일 채택.
- 페르소나 검토에서 A(직후 검증러 — 그린라이트형) 단독은 사례 수집·각색 부담 3-5배. B(통념 검증러 — 매너형) 단독은 영상 후킹 명료. 1차 페르소나 B + A를 B의 후속 파생 콘텐츠로만 운영하는 옵션 X 채택.

## 의사결정 체크포인트 통과 기록

- **Q1 (누구의 어떤 문제)**: 민지(가명), 26세 입사 2년차 직장인 여성. 소개팅 중·직후 통념 갈등 상황(예: 첫만남 더치페이, 연락 텀, 다음 약속 잡는 매너)에서 "내가 이상한 건가" 즉시 검증하고 싶음. 친구 단톡으론 N=3 수준이라 부족, 익명 다수의 정량 의견 갈증. JTBD: "소개팅 중·직후 통념 갈등 상황일 때, 26세 사회초년생은 '내가 이상한 건지' 즉시 검증하고 싶어, 익명 다수의 정량 의견을 1초 안에 받고 싶다." 1차 페르소나 = B 통념 검증러. A 직후 검증러는 B 결과 데이터를 재료로 한 후속 파생 콘텐츠로만 제작.
- **Q2 (증거)**: **추측 단계.** 핫픽 내부 데이터로는 카테고리별 유의미한 참여율 차이 없음 (사용자 인지). 외부 신호 — 유튜브 알고리즘 "민폐·소개팅" 카테고리 트래픽 증가 (사용자 관찰), 디시 소개팅 갤러리·블라인드 연애 게시판 활성도, 네이트판 "썰" 게시판 강세. 검증은 100명 모집 단계에서 자연 발생. **검증 실패 기준**: 100명 중 70% 미만이 소개팅 카테고리 안에서 활동하면 카테고리 라인업 재검토.
- **Q3 (성공·실패 기준)**: 6주 (2026-05-03 ~ 2026-06-14) 내 측정.
  - 성공 KPI: (1) **1회 이상 투표 참여 순수 유저 100명** (TKUID 기준), (2) **영상→웹 CTR 1% 이상** (영상 노출 대비 핫픽 도메인 클릭 비율).
  - 실패 기준: 50명 미만 → 카테고리 라인업 또는 영상 포맷 둘 중 하나 폐기 후 재설계.
  - 보조 추적 (의사결정용): 인스타·X 팔로워 수, 카테고리별 카드 투표 분포, 영상 도달 vs 웹 도달 깔때기.
- **Q4 (자원·기회비용)**: FE 웅일 약 0.5사람-주 (카테고리 폴백 상수 + 화이트리스트 상수 + 디폴트 탭 라우팅 + 탭 배치 순서 변경) + BE 동료 반나절 이내 (Admin API에 신규 `dating` 슬러그 1개만 추가) + 사용자가 어드민에서 소개팅 핏 카드를 수동으로 `dating` 매핑 (반나절~1일 분량) + hotpick-content 콘텐츠 운영 (웅일 6주간 시간의 50%+, 영상 30+편 + 카드 시드 50+장). 포기하는 것 — 번들 핫픽 미구현 추가 진행, 답글·알림 추가 개선. **단, H3 검증(2026-04-25 PRD)은 병렬 진행 가능 영역으로 지정** — 자원 충돌 시 H3 우선.
- **Q5 (가역성)**: **완전 2-way door**. 운영 DB의 기존 카테고리·카드 매핑을 보존하므로 화이트리스트 상수(`VISIBLE_CATEGORY_SLUGS`) 한 줄을 되돌리면 6주 전 상태로 즉시 복귀. **단 1-way door 측면**: "핫픽 = 소개팅 앱"이라는 유저·검색엔진 인식. 한 번 굳으면 다시 펼치기 어려움. 사용자 입장 — "브랜딩은 언제든 변경 가능". 본 문서는 리스크를 명시하되 의사결정은 사용자 입장 존중.

## 검토한 옵션

### 카테고리 라인업 — 옵션 c 채택

| 옵션   | 내용                                                                     | 채택                           |
| ------ | ------------------------------------------------------------------------ | ------------------------------ |
| a      | "소개팅" 단일로 변경, 기존 7개 모두 제거                                 | 미채택 (SEO 자산 손실)         |
| b      | "소개팅" 1순위 + 기존 카테고리 일부 유지                                 | 미채택 (산발 문제 미해결)      |
| c      | "소개팅" + "기타" 2개로 변경, 기존 카드 일괄 `etc` 매핑                  | 미채택 (재매핑 비용·롤백 부담) |
| **c'** | 운영 DB는 보존, 신규 `dating` 슬러그만 추가, FE 화이트리스트로 노출 통제 | **채택**                       |

채택 사유: 운영 DB의 기존 카테고리·카드 매핑을 손대지 않으므로 가역성 최대. 화이트리스트(`VISIBLE_CATEGORY_SLUGS = ['dating']`) 한 줄로 노출 통제. 직접 URL 진입(`/?category=love`)은 여전히 동작해 SEO·롱테일 검색 유입 보존. 사용자가 어드민에서 소개팅 핏 카드만 수동으로 `dating` 추가하므로 시드 큐레이션 품질도 자연스럽게 올라감.

| 옵션 2 | A·B 동등 병렬                        | 미채택 (콘텐츠 부담 2배) |

## 카테고리 정책 변경 명세

### Before

```
[ ✦ NEW   🔥 TOP   가치관 비교   ☑ MY  │  연애  결혼  관계  재테크  직장  라이프  트렌드 ]
```

- 기본 선택: NEW
- 카테고리 7개 모두 탭에 노출, 산발

### After (목표)

```
[ 💘 소개팅  │  ✦ NEW   🔥 TOP   가치관 비교   ☑ MY ]
```

- **기본 선택: 소개팅 카테고리** (메인 진입 시 즉시 소개팅 피드 노출)
- **탭 첫 위치에 소개팅 배치** (필터탭 NEW/TOP/MY 앞)
- 기존 7개 카테고리 탭(연애·결혼·관계·재테크·직장·라이프·트렌드)은 **탭에서 숨김**
- 운영 DB는 그대로 보존 — 카드의 카테고리 매핑 변경 없음
- 직접 URL 진입(`/?category=love` 등)은 여전히 동작 (SEO·롱테일 검색 유입 보존)
- 사용자가 어드민에서 소개팅 핏 카드를 직접 골라 `dating` 카테고리 매핑 추가

### 화이트리스트 정책

FE 상수로 노출 카테고리 통제. 운영 DB나 BE 응답이 어떻든, 화이트리스트에 있는 슬러그만 탭에 표시.

```ts
// src/constants/category.ts
export const VISIBLE_CATEGORY_SLUGS: readonly string[] = ['dating'];
```

- 6주 후 회고에서 다른 카테고리 노출 결정 시 화이트리스트에 슬러그 추가만 하면 됨 (예: `['dating', '민폐']`)
- 정책 폐기 시 화이트리스트 비우거나 기존 7개 슬러그로 되돌리면 즉시 원복

### 카테고리 마스터 변경 (운영 DB)

| 작업                      | 내용                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------ |
| 신규 카테고리 슬러그 추가 | `categories` 테이블에 `dating` (label "소개팅") 1행 INSERT                           |
| 기존 카테고리 보존        | `love`, `marriage`, `relationship`, `finance`, `work`, `life`, `trend` **변경 없음** |
| 기존 hotpick 매핑 보존    | `hotpick_categories` 테이블 변경 없음                                                |
| 신규 카드 생성 시 매핑    | 사용자가 어드민에서 소개팅 핏 카드에 `dating` 카테고리 추가 (수동 큐레이션)          |

BE 동료 작업 부담은 "신규 슬러그 1개 추가"가 전부. 기존 데이터·매핑·롤백 스크립트 모두 불필요.

## Steel-man — 이 결정이 실패한다면

병훈이 한 번 반대편에서 봅니다. 3가지 실패 시나리오 + 대응책.

### 실패 시나리오 1 — 소개팅 콘텐츠가 알고리즘에 안 밀린다

가설: 인스타·쇼츠 알고리즘이 이미 "소개팅" 키워드 포화 상태라 신규 채널은 안 밀어준다. 6주 동안 영상 30편 만들어도 평균 조회수 1천 미만.

대응책:

- Week 2에 **첫 6편 평균 조회수 5천 미만이면 즉시 후킹 포맷 재설계** (썸네일·첫 3초·CTA 위치).
- 후킹 포맷 A/B 테스트 4가지를 Week 1 시드 단계에서 미리 준비.
- 알고리즘 키워드 포화 회피 전략: 직접 "소개팅" 키워드 안 쓰고, "이런 남자 만남" / "어제 만난 사람" 식 우회 표현으로 알고리즘 분류 회피.

### 실패 시나리오 2 — 영상은 잘 되는데 핫픽 웹으로 안 들어온다

가설: 시청자가 댓글창에서 의견 분출하고 끝남. 영상 끝에 CTA 박아도 클릭 1% 미만. CTR 0.3% 수준.

대응책:

- 영상 안에서 결과를 **70%만 공개**하고 30%는 "실시간 결과는 핫픽에서" 클리프행어 처리.
- 영상 카피에 "지금까지 N명 투표 중" 카운터 노출 — 자기 표를 더하고 싶은 충동 유발.
- 인스타 프로필 링크 + 영상 핀 코멘트 + 스토리 링크 트리플 배치.
- Week 3 시점 CTR 0.5% 미만이면 영상 포맷 자체 폐기 (실패 기준 발동).

### 실패 시나리오 3 — 100명 모았는데 70% 핏 안 맞음

가설: 100명 모았지만 그 중 70%가 소개팅 카드 안에서 활동 안 함. 디폴트 진입은 소개팅인데 검색 유입 또는 딥링크로 다른 카테고리(`/?category=love`)에 도달해 거기서만 활동.

대응책:

- 화이트리스트(`VISIBLE_CATEGORY_SLUGS`) 정책 재검토 — Week 4 시점 핏 60% 미만이면 다른 핏 카테고리(예: 민폐, 인간관계) 한 개 추가 노출 검토 (예: `['dating', '민폐']`).
- 신규 유저용 온보딩 화면 1장 추가 검토 — "이 사람 매너인지 핫픽이 정해드립니다" 식 진입 메시지로 카테고리 핏 강화.
- 70% 미만이 곧 라인업 재검토 트리거이므로, 회고 단계에서 "민폐" 또는 "인간관계"로 피벗 옵션 검토. 화이트리스트 한 줄 변경만으로 즉시 시도 가능.
