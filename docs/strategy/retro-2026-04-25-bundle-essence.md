## 회고 대상 요약

Phase 1 실행 중 웅일이 `remind.md`에 자가 회고를 남기면서 번들의 본질 가설 자체를 다시 세움. "혁신의 함정"(주변 의견에 휘둘려 새 아이디어로 도망가는 패턴)을 자각하고, 번들의 원래 목적 — "그룹 단톡방에서 논쟁할 만한 질문으로 웃고 떠들게 만들어 자연스러운 바이럴 유도" — 으로 회귀. 동시에 "긁는 질문 → 프레임 씌우기 → 그룹 비교"의 3단 구조와, MBTI/에겐테토류가 빠지는 함정("이미 내 결과 봤는데 왜 친구랑 비교하지?")에 대한 답으로 **"내가 보기에 너는 이거야" 형 친구 평가 구조**를 새 가설로 도출.

## 결정 검증 (가설 vs 실제)

Phase 1 의사결정 체크포인트의 가설을 하나씩 검증. Phase 1은 아직 출시 전이므로 정량 검증 불가, 정성 신호와 본질 가설의 명확도 변화를 중심으로 점검.

### Q1 (누구의 어떤 문제)

- 가설: 20-40대 한국 청년이 단톡방에서 가볍게 자기 정체성을 확인하고 공유하고 싶을 때, 현재 번들은 "내가 이 그룹에서 어떤 사람인지"를 읽어낼 수 있는 1차 정보로 만들어주지 못함.
- 실제: 가설은 여전히 유효하나 **타겟이 더 좁혀짐** — "단톡방 일반"이 아니라 "구체적 모임(버핏·운동팸·회사·솔로파티·커플 등) 안의 사람들". remind.md line 27, 107의 "대상이 명확해야 한다"는 자각.
- 판정: 부분 맞음.
- 학습: "20-40대 한국 청년 단톡방"은 너무 넓다. 검증 대상은 **웅일이 직접 들어가 운영할 수 있는 1-2개 모임**으로 좁혀야 한다.

### Q2 (증거)

- 가설: N=18 정량 + 인터뷰 4명 정성. "나 중심 정보 위계" + "매칭 로직 어색함" + "결과 자극 부족" 신호 일관됨.
- 실제: 정성 신호는 맞았으나, 웅일이 회고를 거치며 **더 근본적 신호를 발견** — "결과보다 질문 자체가 긁어야 한다"(line 39). 즉 Phase 1이 풀려는 문제(B = 결과 경험)는 진짜 병목이 아닐 수 있음. 진짜 병목은 A(콘텐츠·질문의 자극도).
- 판정: 부분 틀림.
- 학습: 인터뷰 4명에서 잡힌 신호는 정확했지만 **그 신호의 원인을 결과 페이지에 귀속시킨 것이 성급**했을 수 있다. 같은 신호가 "질문이 약했다"로도 해석 가능했음.

### Q3 (성공·실패 기준)

- 가설: 출시 후 2주 내 성공 시그널 4개 (톡방 반응·캡처 공유·2차 링크·테토에겐 참여율) 중 2개 이상.
- 실제: 출시 전이라 측정 불가. 다만 회고를 통해 **시그널 자체의 진단력에 의문**이 생김 — 이 시그널들이 "결과 페이지 재설계의 효과"를 분리해서 측정하지 못함. 콘텐츠(테토/에겐) 변수와 결과 페이지 재설계 변수가 섞여 있음.
- 판정: 측정 불가 + 설계 약점 발견.
- 학습: 다음 검증 사이클은 **변수 1개로 좁힌 실험**으로 설계해야 한다. 한 사이클에 2변수 동시 검증은 결과 해석 어려움.

### Q4 (자원·기회비용)

- 가설: FE 1.5사람-주 + BE 0.3사람-주 + 디자인 1사람-주 + 콘텐츠 0.5사람-주.
- 실제: 진행 중. 다만 **회고가 발견한 진짜 기회비용** — Phase 1을 끝까지 진행하면 H3(친구 평가형)의 빠른 검증이 2주 이상 지연됨. H3는 회고에서 가장 신선한 통찰이므로 지연의 비용이 의외로 큼.
- 판정: 측정 미완 + 기회비용 재평가 필요.
- 학습: 자원 추정은 맞았을 수 있지만 **"이 자원으로 다른 가설을 검증할 기회"** 의 평가가 약했다.

### Q5 (가역성)

- 가설: 2-way door (결과 페이지 재설계·테토에겐 하드코딩 모두 롤백 용이).
- 실제: 그대로. 회고로 인해 Phase 1 자체를 일시 보류·축소하고 H3로 전환하는 것도 기술적으로 가역적.
- 판정: 맞음.
- 학습: 가역성 판단은 정확. 덕분에 지금 회고 결과를 반영해 방향 조정하는 것이 비용 낮음.

## KPT

### Keep — 잘된 것

- **혁신의 함정 자각** (remind.md line 11-13). 다른 사람 의견(윤지·지원·회원)에 휘둘려 새 영역으로 도망가려던 본능을 본인이 잡아냄. 연쇄 피벗 함정 회피.
- **가설을 명문화** (line 25-27, 41). "논쟁할 질문 → 단톡방 공유 → 바이럴"을 글로 적어 검증 가능 형태로 변환.
- **타겟을 "내 주변"으로 다시 좁힘** (line 27). 전국 기준이 아니라 버핏·운동팸 등 구체 모집단으로 회귀. PG의 "do things that don't scale" 원칙 부합.
- **본질 질문 2갈래 압축** (line 113-116). "프레임 공유 vs 질문 비교"로 의사결정 좌표 단순화.
- **싱글-번들 분리 거부** (line 41). "이 가설은 사실 싱글에도 해당된다"는 인식. 형식보다 본질을 먼저 본 것.

### Problem — 문제였던 것

- **솔루션 선결론 → 정당화 패턴** (line 43~71). "프레임 씌우기"로 결론 내고 운동·연애 예시로 디테일 빠져듦. line 113에서 본인이 흔들린 것이 그 증거.
- **"AI가 도와주니까 가능"의 자평 위험** (line 71). 콘텐츠의 진짜 검증은 본인 감각이 아니라 실제 사람 반응. 자평 위험 재발.
- **MBTI/에겐테토 함정의 답이 가설 단계** (line 76-86). 가장 중요한 질문("왜 친구가 들어와야 하지?")에 후보 3개 답을 던졌으나 모두 추측. 검증 안 된 가설 위에 또 가설.
- **Phase 1 설계의 변수 분리 실패** (Q3 학습 참조). 결과 페이지 재설계와 테토/에겐 콘텐츠를 동시 검증해 결과 해석이 어려운 구조.
- **회사 일하듯 정리·디벨롭 안 함** (line 21, 본인 자평). UI/UX/QA 정리 부재. Phase 1 트랙별 정의는 있었으나, 본질 가설의 정리가 부족했다.

## 우리가 틀린 것 (Steel-truth)

1. **우리는 "결과 페이지가 약했다"가 진짜 병목이라고 너무 빨리 단정했습니다.** 같은 인터뷰 신호가 "질문이 약했다"로도 해석 가능했고, 회고는 후자가 더 근본임을 시사합니다. 다음엔 인터뷰 신호 → 원인 가설을 적어도 2개 분리해서 비교한 뒤 실험 설계로 갑니다.
2. **우리는 한 사이클에 변수 2개(결과 재설계 + 테토에겐 콘텐츠)를 같이 태웠습니다.** 결과 해석이 어려운 구조였습니다. 다음 사이클부터 검증 변수는 1개로 좁힙니다.
3. **우리는 "타겟"을 추상으로 두었습니다.** "20-40대 단톡방"은 검증 대상이 아닙니다. "버핏 토요반 12명" 같은 식으로 구체화해야 운영이 돌아갑니다.
