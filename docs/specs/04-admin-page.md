# Admin 페이지 기획서

> 경로: `/admin/trend`

---

## 1. 페이지 목적

트렌드(투표 묶음)를 생성, 수정, 삭제하는 관리자 전용 페이지.

**핵심 기능:**
- 트렌드 목록 조회 및 관리
- 새 트렌드 생성
- 기존 트렌드 수정/삭제
- 5개 선거(Election) 연결

---

## 2. 접근 제한

| 환경 | 접근 |
|------|------|
| development | 접근 가능 |
| production | 404 처리 (접근 불가) |

**보안 정책:**
- 검색 엔진 크롤링 차단 (robots.txt: noindex)
- 프로덕션 배포 시 완전 차단

---

## 3. 페이지 구조

### 3.1 라우팅

| 경로 | 페이지 | 설명 |
|------|--------|------|
| `/admin/trend` | 트렌드 목록 | 전체 트렌드 조회 |
| `/admin/trend/create` | 트렌드 생성 | 새 트렌드 작성 |
| `/admin/trend/edit/{trendId}` | 트렌드 수정 | 기존 트렌드 편집 |

### 5.2 기본 정보 섹션

#### 5.2.1 Alias (필수)

| 항목 | 설명 |
|------|------|
| 용도 | URL 경로용 고유 식별자 |
| 형식 | 영문 소문자, 숫자, 하이픈만 허용 |
| 중복 확인 | 생성 모드에서 필수 |
| 수정 모드 | 변경 불가 (읽기 전용) |

**중복 확인 상태:**

| 상태 | 표시 |
|------|------|
| idle | 회색 버튼 |
| checking | 로딩 스피너 |
| available | 초록색 "사용 가능" |
| duplicate | 빨간색 "이미 사용 중" |

#### 5.2.2 제목 (필수)

| 항목 | 설명 |
|------|------|
| 용도 | 트렌드 메인 제목 |
| 플레이스홀더 | "2025 트렌드" |
| 최대 길이 | 50자 권장 |

#### 5.2.3 부제 (선택)

| 항목 | 설명 |
|------|------|
| 용도 | 서브타이틀/카테고리 |
| 플레이스홀더 | "TREND2025" |
| 최대 길이 | 30자 권장 |

#### 5.2.4 이미지 (필수)

| 항목 | 설명 |
|------|------|
| 개수 | 2개 필수 |
| 용도 | PollCard 썸네일 (좌우 분할) |
| 업로드 방식 | Pre-signed URL (S3) |
| 지원 형식 | JPG, PNG, WebP |
| 권장 크기 | 480x324px 이상 |

### 5.3 연결된 선거 섹션

#### 5.3.1 선거 추가

| 항목 | 설명 |
|------|------|
| 입력 | 선거 ID (외부 시스템에서 생성된 ID) |
| 추가 방법 | "추가" 버튼 클릭 또는 Enter 키 |
| 검증 | 중복 확인, 옵션 개수 확인 |

**검증 규칙:**

| 조건 | 결과 |
|------|------|
| 중복 ID | 에러: "이미 추가된 선거입니다" |
| 옵션 2개 아님 | 에러: "선택지가 2개인 선거만 추가 가능합니다" |
| 유효하지 않은 ID | 에러: "선거를 찾을 수 없습니다" |

#### 5.3.2 선거 카드

추가된 선거는 카드 형태로 표시.

| 요소 | 설명 |
|------|------|
| 드래그 핸들 (≡) | 순서 변경용 |
| 선거 ID | 참조 ID |
| 선거 제목 | Item의 질문 |
| 옵션 목록 | 2개 선택지 표시 |
| 삭제 버튼 | 카드 제거 |

#### 5.3.3 드래그 앤 드롭

선거 카드의 순서를 드래그로 변경 가능.

| 기능 | 설명 |
|------|------|
| 라이브러리 | dnd-kit |
| 센서 | 마우스, 키보드 |
| 애니메이션 | 부드러운 이동 |
| 저장 | 순서 변경 즉시 상태 반영 |

---

### 5.4 폼 검증 규칙

| 필드 | 필수 | 검증 |
|------|------|------|
| alias | O | 중복 확인 완료 (생성 시) |
| title | O | 1자 이상 |
| label | X | - |
| imageUrls | O | 2개 모두 업로드 |
| electionIdList | O | 정확히 5개 |

**제출 조건:**
- 모든 필수 필드 충족
- alias 중복 확인 완료 (생성 시)
- 5개 선거 연결 완료

## 6. 트렌드 수정 페이지

> 경로: `/admin/trend/edit/{trendId}`

### 6.1 수정 가능 항목

| 항목 | 수정 가능 |
|------|----------|
| alias | X (변경 불가) |
| title | O |
| label | O |
| imageUrls | O |
| electionIdList | O (순서, 추가, 삭제) |
| visible | O (공개/비공개) |

### 6.2 위험 영역 (Danger Zone)

수정 페이지 하단에 위치.

```
┌─ 위험 영역 ─────────────────────────────────────────┐
│                                                     │
│  트렌드 삭제                                         │
│  이 작업은 되돌릴 수 없습니다.                        │
│                                          [삭제]     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 6.3 삭제 확인 모달

| 요소 | 내용 |
|------|------|
| 제목 | "트렌드를 삭제하시겠습니까?" |
| 메시지 | "'{트렌드명}'이(가) 영구적으로 삭제됩니다." |
| 취소 버튼 | 모달 닫기 |
| 삭제 버튼 | 빨간색, 삭제 실행 |

**삭제 후:**
- 토스트: "트렌드가 삭제되었습니다"
- `/admin/trend` 페이지로 이동

## 7. 사용자 플로우

### 7.1 트렌드 생성 플로우

```
1. 목록 페이지에서 "+ 트렌드 생성" 클릭
   ↓
2. 생성 폼 페이지로 이동
   ↓
3. Alias 입력 → 중복 확인
   ↓
4. 제목, 부제 입력
   ↓
5. 이미지 2개 업로드
   ↓
6. 선거 ID 5개 추가
   ↓
7. [선택] 순서 드래그로 조정
   ↓
8. "저장" 클릭
   ↓
9. 생성 완료 → 목록 페이지로 이동
```

### 7.2 트렌드 수정 플로우

```
1. 목록에서 "수정" 버튼 클릭
   ↓
2. 수정 폼 페이지로 이동 (기존 데이터 로드)
   ↓
3. 필요한 필드 수정
   ↓
4. "저장" 클릭
   ↓
5. 수정 완료 → 목록 페이지로 이동
```

### 7.3 트렌드 삭제 플로우

```
1. 수정 페이지 하단 "삭제" 클릭
   ↓
2. 확인 모달 표시
   ↓
3. "삭제" 버튼 클릭
   ↓
4. 삭제 완료 → 목록 페이지로 이동
```

## 9. 핵심 UX 원칙

1. **명확한 검증**: 저장 전 모든 필수 조건 충족 확인
2. **즉각적 피드백**: 중복 확인, 선거 검증 등 실시간 응답
3. **실수 방지**: 삭제 시 확인 모달 필수
4. **직관적 순서 변경**: 드래그 앤 드롭으로 쉬운 순서 조정
5. **수정 제한**: Alias는 변경 불가로 URL 안정성 보장
