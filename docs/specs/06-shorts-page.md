# Shorts (단일 투표) 상세 기획서

> 경로: `/shorts/{shortsAlias}` (개별 Shorts)
> Main 페이지(`/`)에서 **별도 탭**으로 독립 노출

---

## 1. 페이지 목적

트렌드(5개 묶음)와 독립적으로 운영되는 **단일 투표**. 하나의 질문에 즉시 투표하고, 그 자리에서 결과를 확인하는 스낵형 콘텐츠.

**핵심 가치:**

- "1초 만에 참여, 1초 만에 결과" — 극한의 가벼움
- 시의성 있는 이슈에 즉시 대응 가능한 콘텐츠 발행
- 콘텐츠 생성 비용 최소화 (이미지 1장 또는 텍스트만으로 발행)

**트렌드 vs Shorts 비교:**

| 항목             | 트렌드 (Trend)        | 단일 투표 (Shorts)   |
| ---------------- | --------------------- | -------------------- |
| 질문 수          | 5개 묶음              | 1개 단독             |
| 옵션 수          | 2개 (이지선다)        | 2~4개                |
| 결과 유형        | 6가지 유형 분류       | 없음 (득표율만 표시) |
| 결과 페이지      | 별도 Result 페이지    | 인라인 (카드 뒤집기) |
| 댓글             | 질문별 독립 댓글      | 1개 댓글 영역        |
| 공유             | 유형 자랑 + 투표 공유 | 투표 공유 (1종)      |
| 투표 UI          | IMAGE 고정            | IMAGE / TEXT 선택    |
| 콘텐츠 생성 비용 | 높음 (이미지 10장+)   | 낮음 (이미지 0~1장)  |

---

## 2. 투표 UI 유형 (voteType)

Shorts는 두 가지 UI 유형을 지원한다.

### 2.1 IMAGE 유형

기존 트렌드 투표와 동일한 방식. 각 옵션마다 이미지 + 텍스트로 구성.

- 옵션 2개: 좌우 분할 (기존 VoteOptionCard 동일)
- 옵션 3~4개: 2x2 그리드 배치
- 메인 이미지 없음 (옵션 이미지가 시각적 역할 대체)

### 2.2 TEXT 유형

메인 이미지 1장 + 텍스트 옵션으로 구성. 콘텐츠 생성 비용을 최소화한 경량 투표.

- 메인 이미지 1장이 질문의 맥락 제공
- 옵션은 텍스트 버튼만으로 구성 (2~4개)
- 이미지 준비가 어려운 질문에 최적

## 3. 화면 구성

### 3.1 Shorts 전용 페이지 레이아웃

개별 Shorts URL(`/shorts/{shortsAlias}`)로 직접 진입하거나 공유 링크로 접속 시.

```
┌────────────────────────────────────┐
│          ShortsHeader              │  ← HotPick 로고 + 홈 버튼
├────────────────────────────────────┤
│                                    │
│                                    │
│          ShortsVoteCard            │  ← 투표 카드 (앞면/뒷면)
│                                    │
│                                    │
├────────────────────────────────────┤
│    [댓글]           [공유]         │  ← 하단 고정 버튼
└────────────────────────────────────┘
```

### 3.2 Main 페이지 Shorts 탭

Main 페이지 상단 탭에서 "Shorts" 탭 선택 시 노출되는 전용 피드. 트렌드와 완전히 분리된 독립 탭.

```
┌────────────────────────────────────┐
│           MainHeader               │  ← 로고 + 슬로건
├────────────────────────────────────┤
│   [ 트렌드 ]  [ ⚡Shorts ]         │  ← 탭 네비게이션
├────────────────────────────────────┤
│          ShortsCard 1              │
├────────────────────────────────────┤
│          ShortsCard 2              │
├────────────────────────────────────┤
│          ShortsCard 3              │
├────────────────────────────────────┤
│               ...                  │
│          (무한스크롤)               │
└────────────────────────────────────┘
```

**탭 분리 결정 근거:**

| 근거           | 설명                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 콘텐츠 비대칭  | Shorts는 제작이 쉬워 발행량이 빠르게 증가 → 혼합 피드에서 트렌드가 묻힘      |
| 참여 깊이 차이 | 트렌드(5개 묶음, 유형 분류)와 Shorts(단일, 즉시 결과)는 근본적으로 다른 경험 |
| 산업 표준      | Instagram Reels탭, YouTube Shorts탭 — 타겟(20~40대)이 이미 익숙한 패턴       |
| 독립 최적화    | 탭별 정렬/필터/알고리즘을 독립적으로 최적화 가능                             |
| 사용자 의도    | "빠르게 Shorts만" vs "깊이 있는 트렌드 참여" 의도가 명확히 다름              |

```

│ │  [옵션1 이미지]  │ [옵션2 이미지]  │ │  ← 2개: 좌우 분할
│ │                 │                │ │
│ └─────────────────┴────────────────┘ │
│                                      │
│  짜장면 vs 짬뽕, 당신의 선택?          │  ← 제목
```

## 8. 투표 중복 방지

Shorts는 비로그인 서비스이므로 기기 기반으로 중복 투표를 방지한다.

### 8.1 방식

| 구분 | 방법                                                 |
| ---- | ---------------------------------------------------- |
| 1차  | localStorage에 투표한 shortsId 저장                  |
| 2차  | 서버에서 fingerprint(IP + User-Agent) 기반 중복 체크 |

### 8.2 localStorage 구조

```json
{
  "hotpick_shorts_votes": {
    "shorts_abc123": {
      "optionId": "opt_1",
      "votedAt": "2025-02-13T10:30:00Z"
    },
    "shorts_def456": {
      "optionId": "opt_3",
      "votedAt": "2025-02-13T11:00:00Z"
    }
  }
}
```

### 8.3 재방문 시 동작

```
1. Shorts 페이지 진입
   ↓
2. localStorage에서 해당 shortsId 투표 기록 확인
   ↓
3-a. 기록 있음 → 서버에서 현재 결과 조회 → 뒷면(결과) 렌더링
3-b. 기록 없음 → 앞면(투표) 렌더링
```

## 16. 핵심 UX 원칙

1. **극한의 가벼움**: 하나의 질문, 하나의 탭, 즉시 결과. 3초 안에 투표 완료.
2. **탭 분리로 명확한 경험**: 트렌드와 별도 탭으로 운영하되, 전체적인 디자인 언어는 통일.
3. **콘텐츠 생성 용이**: TEXT 유형으로 이미지 1장 + 텍스트만으로 즉시 발행.
4. **기존 패턴 재사용**: 카드 뒤집기, 댓글 바텀시트, 프로그레스 바 등 검증된 인터랙션 패턴 유지.
5. **점진적 공개**: 투표 전에는 옵션만, 투표 후에 결과 + 댓글 + 공유 버튼 등장.

## 17. 에지 케이스 처리

### 17.1 투표 진행 중 마감 발생

사용자가 Shorts 페이지를 열어둔 상태에서 서버 측 마감 시간이 도래한 경우.

| 시점                         | 처리                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| 페이지 진입 시 이미 마감     | 앞면(투표) 대신 뒷면(결과) 바로 표시 + "마감된 투표입니다" 안내      |
| 옵션 탭 시 서버에서 410 반환 | 토스트: "마감된 투표입니다" → 현재 결과 재조회 → 뒷면(결과)으로 전환 |
| 결과 표시 중 마감            | 영향 없음 (이미 투표 완료)                                           |

**프론트엔드 처리 흐름:**

```
1. 사용자가 옵션 탭
   ↓
2. POST /api/shorts/{id}/vote 호출
   ↓
3-a. 200 OK → 정상 카드 뒤집기 + 결과 표시
3-b. 410 CLOSED → 토스트 "마감된 투표입니다"
     → GET /api/shorts/{id} 재호출
     → 결과 상태로 렌더링 (내 선택 없음)
3-c. 409 ALREADY_VOTED → 토스트 "이미 투표한 Shorts입니다"
     → localStorage 동기화 → 결과 상태로 렌더링
```

### 17.2 마감 시간 기준

| 항목              | 기준                                                           |
| ----------------- | -------------------------------------------------------------- |
| 마감 판정         | 서버 시간(UTC) 기준                                            |
| 프론트 카운트다운 | 서버 응답의 deadline과 클라이언트 시간 차이로 표시 (오차 허용) |
| 자동 마감         | 서버 스케줄러가 1분 주기로 deadline 도래 Shorts를 CLOSED 처리  |
| Admin 마감일 검증 | 서버에서 현재 시간(UTC) + 1시간 이후만 허용                    |

### 17.3 옵션 개수 관련

| 시나리오                        | 처리                                             |
| ------------------------------- | ------------------------------------------------ |
| Admin 생성 폼: 옵션 추가        | "+" 버튼 클릭 시 빈 옵션 행 추가 (최대 4개까지)  |
| Admin 생성 폼: 옵션 삭제        | 옵션이 3개 이상일 때만 삭제 가능 (최소 2개 보장) |
| Admin 수정 폼: 옵션 개수 변경   | 불가 — 이미 투표된 데이터의 정합성 보장을 위해   |
| 옵션 텍스트가 빈 채로 저장 시도 | "모든 옵션의 텍스트를 입력해주세요" 에러 표시    |

### 17.4 이미지 로딩 실패

| 유형       | 실패 대상     | 처리                                                  |
| ---------- | ------------- | ----------------------------------------------------- |
| IMAGE 유형 | 옵션 이미지   | placeholder 이미지로 대체 (회색 배경 + 카메라 아이콘) |
| TEXT 유형  | 메인 이미지   | placeholder 이미지로 대체 (회색 배경 + 카메라 아이콘) |
| ShortsCard | 썸네일 이미지 | 동일 placeholder 처리                                 |

### 17.5 동시성 이슈

| 시나리오                         | 처리                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| 같은 기기에서 두 번 투표 시도    | localStorage 체크로 1차 차단 → 서버 fingerprint 체크로 2차 차단 (409)  |
| 다른 기기에서 동일 사용자 투표   | 허용 (비로그인 서비스 한계 — 추후 로그인 도입 시 개선)                 |
| 투표 직후 새로고침               | localStorage 기록 존재 → 결과 상태로 렌더링                            |
| localStorage 삭제 후 재투표 시도 | 서버 fingerprint 체크에서 409 반환 → "이미 투표한 Shorts입니다" 토스트 |

| GET /api/shorts (목록)        | staleTime: 30초, 무한스크롤 페이지별 캐시, 탭 전환 시 보존 |
| GET /api/shorts/{id}          | staleTime: 10초 (투표 결과 실시간성 고려)                  |
| GET /api/shorts/{id}/comments | staleTime: 30초, 댓글 작성 시 invalidate                   |
| GET /api/categories           | staleTime: 5분 (거의 변경 안 됨)                           |
| GET /api/trends (트렌드 탭)   | 기존 캐싱 전략 유지, Shorts 탭과 독립 캐시                 |

### 19.3 번들 최적화

| 전략          | 설명                                                             |
| ------------- | ---------------------------------------------------------------- |
| 코드 분할     | Shorts 관련 컴포넌트는 dynamic import (Next.js의 `next/dynamic`) |
| 공용 컴포넌트 | CommentBottomSheet, DeadlineBadge 등은 common 번들에 포함        |
| Admin 페이지  | 별도 chunk로 분리 (일반 사용자는 로드하지 않음)                  |

## 20. Main 페이지 탭 상세 규칙

### 20.1 탭 URL 연동

| URL                    | 활성 탭          |
| ---------------------- | ---------------- |
| `/` 또는 `/?tab=trend` | 트렌드 탭 (기본) |
| `/?tab=shorts`         | Shorts 탭        |

브라우저 뒤로가기/앞으로가기 시 탭 상태 복원. `useSearchParams`로 URL 쿼리와 탭 상태 동기화.

### 20.2 탭별 카테고리 필터

각 탭의 카테고리 필터는 **독립적으로 동작**.

| 시나리오             | 트렌드 탭                                                           | Shorts 탭              |
| -------------------- | ------------------------------------------------------------------- | ---------------------- |
| "전체" 선택 (기본)   | 모든 트렌드 표시                                                    | 모든 Shorts 표시       |
| 특정 카테고리 선택   | 해당 카테고리 트렌드만                                              | 해당 카테고리 Shorts만 |
| 카테고리 없는 콘텐츠 | "전체"에서만 표시                                                   | "전체"에서만 표시      |
| 탭 전환 시 카테고리  | 탭별 독립 유지 (트렌드 #음식 선택 후 Shorts 전환 → Shorts는 "전체") |

### 20.3 탭별 페이지네이션

| 항목              | 규칙                                       |
| ----------------- | ------------------------------------------ |
| 페이지네이션 방식 | 각 탭 독립적 무한스크롤 (page 기반)        |
| 탭 전환 시        | 기존 로드된 데이터 보존, 스크롤 위치 보존  |
| 새 콘텐츠 추가 시 | Pull-to-Refresh로 갱신                     |
| 삭제된 콘텐츠     | 다음 요청 시 반영                          |
| size 파라미터     | 각 탭 독립 (Shorts size=20, Trend size=20) |

### 20.4 탭 전환 시 데이터 전략

| 전략                | 설명                                                         |
| ------------------- | ------------------------------------------------------------ |
| React Query 캐시    | 각 탭의 queryKey가 다르므로 캐시가 독립적으로 관리됨         |
| Prefetch            | 비활성 탭 첫 페이지를 백그라운드에서 prefetch (staleTime 내) |
| 스크롤 복원         | `useRef`로 각 탭의 scrollTop을 저장/복원                     |
| 탭 전환 시 API 호출 | staleTime 이내면 캐시 사용, 초과 시 refetch                  |

### 20.5 탭 컴포넌트 구현 가이드

```typescript
// useMainTab.ts
import { useSearchParams } from 'next/navigation';

type MainTab = 'trend' | 'shorts';

export function useMainTab() {
  const searchParams = useSearchParams();
  const activeTab: MainTab = (searchParams.get('tab') as MainTab) || 'trend';

  const setTab = (tab: MainTab) => {
    const params = new URLSearchParams(searchParams);
    if (tab === 'trend') {
      params.delete('tab'); // 기본값은 URL에서 생략
    } else {
      params.set('tab', tab);
    }
    window.history.pushState(null, '', `?${params.toString()}`);
  };

  return { activeTab, setTab };
}
```
