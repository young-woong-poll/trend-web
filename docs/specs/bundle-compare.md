# 번들 가치관 비교 기능 기획서

> **작성일**: 2026-03-27 (최종 수정: 2026-03-30)
> **상태**: 설계 완료
> **작성 목적**: "번들 퍼스트" 전략의 핵심 피처. 번들 가치관 비교를 통해 HotPick을 "투표 서비스"에서 "관계 비교 도구"로 포지셔닝 전환
> **전략 배경**: 유사 서비스(Pickhana)와의 차별화를 위해 "MBTI 궁합 테스트의 실제 고민 업그레이드" 포지션 선점

---

## 1. 컨셉

### 1.1 한 줄 정의

> **"우리 생각 얼마나 통할까?"**

한 주제에 관련하여 가치관이 드러나는 질문 5~10개를 묶어 하나의 Bundle로 만들고, 친구·연인·동료에게 공유하면 서로의 답변을 비교할 수 있는 기능. HotPick의 핵심 성장 엔진이자 바이럴 루프의 시작점.

### 1.2 핵심 가치

| 항목      | 싱글 Hotpick (리텐션 보조)    | 번들 가치관 비교 (핵심 성장 엔진)         |
| --------- | ----------------------------- | ----------------------------------------- |
| 핵심 질문 | "나는 어떤 편일까?"           | "우리는 얼마나 통할까?"                   |
| 형태      | 1문항, 즉시 결과              | 5~10문항, 종합 결과                       |
| 참여 방식 | 혼자 확인                     | 비교 링크로 함께 참여                     |
| 성장 역할 | 번들로 유입된 유저의 리텐션   | 초대 → 참여 → 비교 → 재공유 바이럴 루프   |
| 경쟁 우위 | Pickhana와 유사 (차별화 약함) | MBTI 궁합 테스트의 "실제 고민" 업그레이드 |

> **번들 퍼스트 원칙**: 랜딩/공유에서는 번들 비교 중심, 피드에 들어오면 싱글도 자연스럽게 노출. 싱글과 번들은 완전히 독립된 엔티티로 운영.

## 2. 전제 조건

- **카카오 OAuth 로그인** 필수 (번들 풀기, 비교 기능 모두)
- 회원가입 시 **고유 닉네임 필수**, 성별/생년월일 선택
- 번들 인트로/비교 링크 랜딩은 비로그인으로 열람 가능하나, 참여 시 로그인 유도

## 3. 번들 구성

### 3.1 번들 정의

- 하나의 주제(테마)에 대한 가치관이 드러나는 Hotpick 묶음
- **질문 수**: 최소 5개 ~ 최대 10개
- **번들 전용 Hotpick**: 싱글 Hotpick과 독립된 엔티티 (데이터 완전 분리)

### 3.2 싱글-번들 완전 분리 정책

번들 Hotpick과 싱글 Hotpick은 **완전히 독립된 엔티티**로 운영한다.

- 번들 Hotpick은 번들 내에서만 투표/조회 가능, 싱글 피드에 노출하지 않음
- 싱글 Hotpick은 싱글 피드에서만 투표/조회 가능, 번들에 포함하지 않음
- 동일 주제의 질문이 싱글과 번들에 각각 존재할 수 있으나, **투표 데이터는 별도 집계**
- 대중성 지수는 **번들 참여자 모수만으로** 계산

### 3.3 메인 피드 노출 (싱글 피드 내 번들 카드)

번들은 싱글 피드 안에 **구분된 디자인의 번들 카드**로 삽입하여 노출한다.

- 싱글 Hotpick 리스트 중간에 번들 카드를 배치 (예: 5~10개마다 1장)
- 번들 카드는 싱글 카드와 **명확히 다른 디자인** (그라디언트 테두리, 배지, 카드 크기 등)으로 구분
- 번들 카드 탭 시 → 번들 인트로 페이지(`/bundle/{slug}`)로 이동
- 번들 카드에 표시할 정보: 테마 아이콘, 번들 제목, 부제, 질문 수, 참여자 수
- 노출 순서/빈도는 어드민 설정 또는 알고리즘으로 관리

### 3.4 번들 생성 주체

- **1차**: 어드민이 직접 큐레이션 (기존 Hotpick에서 선별 or 신규 생성)
- **추후**: 자동 큐레이션 (위클리 HOT 등) 및 UGC 형태 확장 고려

### 3.5 번들 큐레이션 유형

| 유형           | 설명                                    | 갱신 주기    | 예시                                        |
| -------------- | --------------------------------------- | ------------ | ------------------------------------------- |
| **테마 번들**  | 특정 주제로 묶은 고정 콘텐츠            | 상시         | "결혼 가치관", "직장인 생존", "연애 스타일" |
| **시즌 번들**  | 계절·시기에 맞는 테마 큐레이션          | 월 1~2회     | "2026 여름휴가 밸런스 게임"                 |
| **위클리 HOT** | 해당 주 최다 참여 Hotpick 자동 큐레이션 | 매주         | "이번 주 HOT 7"                             |
| **이슈 번들**  | 시의성 있는 이슈 모음                   | 이슈 발생 시 | "AI 시대 논쟁 TOP 5"                        |

### 3.6 테마 번들 예시

#### 결혼 가치관 테스트 (5문항)

1. 혼수 비용, 각자 알아서 vs 반반
2. 맞벌이 vs 한쪽이 집에
3. 신혼집 매매 vs 전세
4. 시댁·처가 명절 매년 vs 격년
5. 아이 교육 사교육 vs 자율

#### 직장인 생존 테스트 (5문항)

1. 연봉 500 올려주는 이직 vs 편한 현 직장
2. 칼퇴 vs 야근하고 성과급
3. 좋은 상사 + 별로인 일 vs 별로인 상사 + 좋아하는 일
4. 대기업 안정 vs 스타트업 스톡옵션
5. 퇴근 후 업무 카톡 답장 vs 무시

#### 연애 스타일 테스트 (5문항)

1. 썸 탈 때 먼저 연락 vs 기다리기
2. 연인 전 애인 사진 지워야 함 vs 상관없음
3. 기념일 챙기는 편 vs 별로
4. 연인 이성 친구 만남 OK vs NO
5. 싸우면 바로 풀기 vs 혼자 정리하고 대화

## 4. 사용자 플로우

### 4.1 번들 풀기 (공통)

```
[메인 피드 (싱글 Hotpick 리스트)]
  │ 피드 중간에 삽입된 번들 카드 탭
  ▼
[번들 인트로 페이지]  ← 비로그인도 열람 가능
  │ 테마 소개 + "시작하기" CTA
  │ (미로그인 시 카카오 로그인 유도)
  ▼
[질문 1/N] → [질문 2/N] → ... → [질문 N/N]
  │ 프로그레스 바 표시
  │ 각 질문 = 번들 전용 Hotpick (2지선다)
  ▼
[내 결과 확인]
  │ 종합 결과 카드 + 각 질문별 내 선택 요약
  │ 대중성 지수 + 대중성 캐릭터
  ├──▶ "1:1 비교하기" CTA
  └──▶ "그룹 비교하기" CTA
```

### 4.2 비교 링크 종류

| 타입          | 설명            | 특징                                |
| ------------- | --------------- | ----------------------------------- |
| **1:1 비교**  | 특정 1명과 비교 | 1명만 참여 가능                     |
| **그룹 비교** | 여러 명과 비교  | 그룹 이름 + 최대 인원 설정 (2~20명) |

비교 링크는 **번들을 모두 풀었을 때만** 생성 가능.

### 4.3 1:1 비교 흐름

1:1 링크는 생성자 외 **최초 1명만** 참여 가능. 링크에 진입한 첫 번째 유저가 자동으로 매핑된다.

```
[내 결과 페이지] → "1:1 비교하기"
  │
  ▼
[1:1 비교 링크 생성]
  │ 공유 방법: 카카오톡 / 링크 복사
  │ 공유 메시지: "{닉네임}님이 비교를 기다리고 있어요!"
  ▼
[상대방이 링크 클릭] ← 최초 1명만 참여 가능
  │
  ├─ 이미 번들 완료 → 자동 매핑 → 비교 결과 페이지
  │
  ├─ 아직 미완료
  │   │ 안내: "{닉네임}님과의 비교 결과가 기다리고 있어요!"
  │   ▼
  │   [번들 풀기] → [완료] → [자동 매핑] → [비교 결과 페이지]
  │
  └─ 이미 다른 사람이 참여 완료
      안내: "이미 참여가 완료된 링크입니다"
```

> 1:1 링크의 생성자 본인이 자신의 링크에 진입하면 참여자가 아직 없을 경우 대기 안내, 참여 완료 시 비교 결과로 이동.

### 4.4 그룹 비교 흐름

```
[내 결과 페이지] → "그룹 비교하기"
  │
  ▼
[그룹 생성]
  │ 그룹 이름 입력 (예: "마케팅팀")
  │ 최대 인원 설정 (2~20명)
  │ → 그룹 링크 생성
  ▼
[단톡방 등에 링크 공유]
  │
  ▼
[멤버들이 링크 클릭]
  │ 안내: "{닉네임}님의 '{그룹이름}' 그룹에 참여하세요!"
  │ 안내: "번들을 모두 풀어야 그룹에 참여할 수 있어요"
  ├─ 이미 완료 → 그룹 합류 → 비교 결과
  └─ 미완료
      │ 안내: "'{번들 제목}' 번들을 풀면 바로 비교 결과를 확인할 수 있어요!"
      │ CTA: "번들 풀고 참여하기"
      ▼
      [번들 풀기] → [완료] → [자동 그룹 합류] → [비교 결과]
```

- 같은 비교 링크로 들어온 사람들이 하나의 **그룹**으로 묶임
- 그룹 내 멤버끼리 **크로스 1:1 비교** 가능
- 그룹 전체 **통계/인사이트** 제공
- 생성자가 원하는 시점에 **그룹 마감** 가능 (더 이상 합류 불가)
- 같은 번들에 **여러 그룹 생성** 가능 (예: "회사 동료" 그룹, "대학 친구" 그룹)

### 4.5 이미 둘 다 풀었으면 바로 비교

비교 링크 없이도, 해당 번들을 이미 둘 다 완료한 상태이고 같은 비교 그룹에 속해 있다면 바로 비교 결과를 확인할 수 있다.

### 4.6 비교 관리

마이페이지에서 **내가 참여한 번들**과 **내가 생성한 비교 링크**를 분리하여 관리한다.

```
[마이페이지]
  │
  ├─ [내가 참여한 번들]
  │   ├─ 결혼 가치관 ──┬─ 1:1: vs 수진 (케미 A)
  │   │                └─ 그룹: "마케팅팀" (4/5명 참여)
  │   └─ 직장인 생존 ── 1:1: vs 철수 (케미 S)
  │
  └─ [내가 생성한 비교 링크]
      ├─ 결혼 가치관 ──┬─ 그룹: "마케팅팀" (4/5명, 진행중) [수정] [마감]
      │                └─ 그룹: "대학 동기" (7/10명, 마감)
      └─ 직장인 생존 ── 그룹: "개발팀" (3/8명, 진행중) [수정] [마감]
```

#### 비교 링크 수정 기능 (생성자 전용)

생성자는 진행 중인 그룹 비교 링크의 설정을 수정할 수 있다.

수정 가능 항목:

- **그룹 이름**: 언제든 변경 가능
- **최대 인원**: 현재 참여 인원 이상으로만 변경 가능
- **마감 여부**: 마감 → 재오픈 가능

제약 조건:

- 이미 참여한 인원보다 적은 수로 최대 인원을 줄일 수 없음 (예: 5명 참여 중 → 4명 이하로 변경 불가)
- 마감된 그룹은 재오픈 가능
- 1:1 비교 링크는 수정 불가 (상대방 1명 고정)
- 비교 링크 삭제는 불가 (데이터 보존, 노출만 숨김 처리)

## 5. 비교 결과 시스템

### 5.1 케미 등급 체계

| 일치율  | 등급 | 타이틀     | 한줄평                                           |
| ------- | ---- | ---------- | ------------------------------------------------ |
| 90~100% | S    | 소울메이트 | "전생에 한 몸이었나? 생각이 이렇게 같을 수가"    |
| 70~89%  | A    | 찰떡궁합   | "대부분 통하는데, 가끔 깜짝 놀랄 포인트가!"      |
| 50~69%  | B    | 밀당 케미  | "반은 같고 반은 다르고, 이게 진짜 케미 아닐까?"  |
| 30~49%  | C    | 반전 매력  | "다른 점이 더 많아서 오히려 재밌는 사이"         |
| 0~29%   | D    | 평행우주   | "같은 세상 살고 있는 거 맞아? 그래도 그게 매력!" |

> 모든 등급이 긍정적 톤을 유지한다. 낮은 일치율도 "재미 포인트"로 전환.
> 각 등급은 고유한 3D 캐릭터 이미지 에셋으로 시각화. 등급별 포인트 색상과 조합하여 표시.

### 5.2 번들 테마별 맞춤 해석

번들 생성 시 어드민이 등급별 맞춤 문구를 설정한다. 같은 S등급이라도 테마마다 다른 재미를 준다.

| 테마        | S등급                           | D등급                                 |
| ----------- | ------------------------------- | ------------------------------------- |
| 결혼 가치관 | "이 정도면 혼인신고 바로 가능"  | "결혼 전 진지한 대화가 필요할지도..." |
| 직장인 생존 | "같은 팀 하면 시너지 폭발할 듯" | "회의 때 싸울 확률 99%"               |
| 연애 스타일 | "이상형이 서로인 거 아닌가요?"  | "밀당의 신이 탄생했습니다"            |

### 5.3 1:1 비교 결과 구성 (재미 위주)

#### 케미 카드 (상단)

- 케미 등급 + 타이틀 + 테마별 맞춤 한줄평
- 일치율 % 크게 표시
- 등급별 포인트 색상 차별화

#### 가장 충격적인 차이

다른 답을 고른 질문 중, 대중 투표에서 비율이 가장 극단적으로 갈린 질문을 "충격 포인트"로 강조.

```
[가장 충격적인 차이]

"시댁 명절 매년 vs 격년"

민수: 매년 (대중 27%)
수진: 격년 (대중 73%)

"민수님, 이건 좀 양보하셔야..."
```

상대방이 다수파인데 나는 소수파인 경우 더 재밌는 코멘트 생성.

#### 대중성 포지션 비교

각자의 대중성 지수(다수파와 같은 답 비율)를 비교하여 캐릭터 부여.

**서버-클라이언트 역할 분리:**

- **서버**: 각 질문별 투표 비율(optionA%, optionB%)과 유저의 선택만 리턴
- **FE**: 투표 비율 데이터를 바탕으로 대중성 지수 계산 + 등급/캐릭터/문구 매핑
- 대중성 수치는 다른 유저의 투표가 진행될수록 변동됨. 결과 페이지 재방문 시 최신 비율 기준으로 재계산

```
대중성 지수 = (다수파와 같은 답 개수 / 전체 질문 수) × 100
```

| 대중성 | 캐릭터      | 설명                          |
| ------ | ----------- | ----------------------------- |
| 90%+   | 여론 장악자 | "대중의 마음을 꿰뚫어 봄"     |
| 70~89% | 트렌드 리더 | "시대를 읽는 눈이 있음"       |
| 50~69% | 밸런서      | "어느 쪽이든 이해하는 균형파" |
| 30~49% | 소신파      | "남들과 다른 길을 가는 타입"  |
| ~29%   | 유니콘      | "세상에 없는 독보적 가치관"   |

> 각 캐릭터는 3D 이미지 에셋으로 제공. FE에서 등급에 따라 해당 이미지를 매핑하여 표시.

#### "같은 편인 순간 / 갈린 순간" 스토리텔링

단순 나열이 아니라, 같은 답들의 공통점을 한 문장으로 요약.

```
[우리가 같은 편인 순간] (3/5)

"혼수는 각자, 맞벌이는 당연, 신혼집은 전세부터!"
→ 현실적인 결혼 준비를 지향하는 두 사람. 큰 그림에선 통한다!

[우리가 갈린 순간] (2/5)

· 명절: 민수 "매년" vs 수진 "격년"
· 육아: 민수 "어린이집" vs 수진 "직접"
→ 가족·육아 관련해서 대화가 필요한 포인트!
```

어드민이 번들 생성 시 질문 조합별 해석 문구를 설정.

### 5.4 그룹 비교 결과 구성 (인사이트 위주)

#### 그룹 통계

- **그룹 싱크율**: 모든 멤버 쌍의 일치율 평균 (예: 5명 → C(5,2)=10개 쌍의 일치율 평균)
- **만장일치 질문**: 전원이 같은 답을 고른 질문 (만장일치 뱃지)
- **논쟁 포인트**: 가장 의견이 갈린 질문 (논쟁 포인트 뱃지)
- **질문별 답변 분포**: 가로 막대 차트로 비율 시각화

#### 가치관 지도 (MBTI 스타일 4분면)

MBTI가 N/S, T/F로 4분면을 만드는 것처럼, 번들의 질문들을 2개 축에 배정하여 4분면 포지션을 시각화한다.

**축 설정 방식**

어드민이 번들 생성 시 2개의 축을 정의하고, 각 질문을 축 하나에 배정한다. 가중치가 아닌 단순 배정 방식으로, 어드민 설정이 간단하다.

```
[번들 생성 시 어드민 설정]

1. X축 정의: "현실주의 ↔ 이상주의"
   - 옵션 A가 왼쪽(현실), 옵션 B가 오른쪽(이상)
2. Y축 정의: "개인 중심 ↔ 관계 중심"
   - 옵션 A가 아래(개인), 옵션 B가 위(관계)

3. 질문별 축 배정 (각 질문은 하나의 축에만 배정):
   ┌──────────────────────────┬──────┬────────────────────┐
   │ 질문                     │ 축   │ 옵션 A → / 옵션 B → │
   ├──────────────────────────┼──────┼────────────────────┤
   │ 혼수 각자 vs 반반        │ X축  │ A→현실 / B→이상     │
   │ 신혼집 매매 vs 전세      │ X축  │ A→이상 / B→현실     │
   │ 사교육 vs 자율           │ X축  │ A→이상 / B→현실     │
   │ 맞벌이 vs 한쪽이 집에    │ Y축  │ A→개인 / B→관계     │
   │ 명절 매년 vs 격년        │ Y축  │ A→관계 / B→개인     │
   └──────────────────────────┴──────┴────────────────────┘

4. 좌표 계산 (FE에서):
   X = (해당 축 질문 중 오른쪽 답 개수 / 해당 축 질문 수) × 2 - 1
   Y = (해당 축 질문 중 위쪽 답 개수 / 해당 축 질문 수) × 2 - 1
   → 범위: -1 ~ +1
```

- 서버는 각 질문의 축 배정 정보(`axis: 'X' | 'Y'`)만 리턴, 좌표 계산은 FE에서 처리
- 축에 배정되지 않은 질문도 가능 (`axis: null`), 해당 질문은 지도에 반영되지 않음
- 그룹 평균 = 전체 멤버 좌표의 X평균, Y평균 (점선 원으로 표시)
- 4분면 각각에 테마에 맞는 라벨 표시 (예: "현실적 개인주의자", "이상적 관계중심파" 등)

#### 케미 네트워크

- 멤버 간 1:1 궁합을 관계도로 시각화
- 선 두께 = 케미 등급 (두꺼울수록 높은 궁합)
- 등급별 색상 차별화 (S: 골드, A: 퍼플, B: 오렌지, C: 블루, D: 그린)

#### 그룹 어워드 (칭호 자동 부여)

| 칭호        | 기준                              | 한줄평                                      |
| ----------- | --------------------------------- | ------------------------------------------- |
| 그룹 대장   | 그룹 평균과 가장 일치율 높은 사람 | "이 그룹의 가치관을 대표합니다"             |
| 그룹 이단아 | 그룹 평균과 가장 먼 사람          | "혼자만 다른 세계에 사는 중"                |
| 소울 커넥션 | 그룹 내 최고 1:1 궁합 조합        | "통하는 게 느껴지나요?"                     |
| 극과 극     | 그룹 내 최저 1:1 궁합 조합        | "토론하면 밤새겠다"                         |
| 논쟁 메이커 | 가장 많이 소수파에 속한 사람      | "매번 반대편에 서는 당신, 혹시 일부러?"     |
| 대중의 왕   | 대중성 지수가 가장 높은 사람      | "세상이 어떻게 돌아가는지 정확히 아는 사람" |

> 각 칭호는 전용 3D 이미지 에셋으로 시각화. 이모지 대신 브랜드 톤에 맞는 일러스트를 사용하여 AI 생성물 느낌을 배제.

#### 멤버별 1:1 비교 리스트

- 각 멤버와의 케미 등급 + 일치율 표시
- 탭하면 1:1 상세 비교로 이동

#### 그룹 간 내 포지션 비교

같은 번들을 여러 그룹에서 비교했을 때, 그룹마다 내 대중성 캐릭터가 달라질 수 있음.

```
"마케팅팀"에서 나는: 트렌드 리더 → 그룹 평균과 비슷
"대학 동기"에서 나는: 소신파 → 이 그룹에선 꽤 독특한 답변

"같은 가치관이라도 누구와 비교하느냐에 따라 나의 포지션이 달라져요!"
```

### 5.5 결과 공유

- **링크 공유**: 비교 결과 웹 페이지 링크 (카카오톡 / 링크 복사)
- **화면 캡처**: 유저가 직접 캡처하여 공유. 결과 페이지를 캡처하기 좋은 레이아웃으로 디자인
- 별도 이미지 생성 기능은 제공하지 않음 (개발 비용 대비 유저가 직접 캡처하는 것이 자연스러움)

#### 디자인 톤

- 기존 HotPick 다크 테마 (#121212 배경)
- 케미 등급별 포인트 색상 차별화
  - S등급: 골드 그라디언트
  - A등급: 마젠타-퍼플 그라디언트
  - B등급: 오렌지-마젠타 그라디언트
  - C등급: 블루-시안 그라디언트
  - D등급: 그린-시안 그라디언트
- 워터마크: 하단에 `hotpick.kr` + 슬로건

#### 이모지 사용 원칙

서비스 UI에서 이모지를 과도하게 사용하면 AI 생성물 느낌을 줄 수 있다. 통일성 있는 화면을 위해 다음 원칙을 따른다.

- **캐릭터/등급 시각화**: 이모지 대신 **3D 캐릭터 이미지 에셋**을 사용 (케미 등급 5종, 대중성 등급 5종, 그룹 어워드 6종)
- **섹션 구분**: 이모지 대신 **아이콘 컴포넌트** 또는 **색상 구분선**으로 섹션 구분
- **문구 내 이모지**: 사용하지 않음. 텍스트는 텍스트로만, 시각적 강조는 색상/폰트 웨이트로 처리
- **공유 카드 이미지**: 3D 캐릭터 이미지 + 등급 색상으로 시각적 임팩트 확보

## 6. 바이럴 루프

### 6.1 비교 기능 바이럴 루프

핵심: 참여자가 **받은 링크를 재공유하는 것이 아니라**, 자신의 비교 링크를 **새로 생성**하여 공유한다.

```
A가 번들 풀기 → 비교 링크 생성 → B에게 초대
                                     │
                                     ▼
                              B가 번들 풀기
                                     │
                              ┌──────┴──────┐
                              ▼             ▼
                        A와 비교 결과    B의 결과 페이지
                              │             │
                              ▼             ▼
                        "나도 비교해보기"   "내 비교 링크 만들기"
                        (결과 페이지 CTA)  (결과 페이지 CTA)
                              │             │
                              ▼             ▼
                        B가 자신의        B가 자신의
                        비교 링크 생성    비교 링크 생성
                        → C에게 초대      → D에게 초대
```

**참여자의 비교 링크 생성 유도 UX:**

비교 링크를 통해 번들을 완료한 참여자에게는 비교 결과 확인 후 다음 CTA를 노출:

- "다른 친구와도 비교해볼래?" → 자신의 1:1 비교 링크 생성
- "그룹으로 비교해볼래?" → 자신의 그룹 비교 링크 생성

이 CTA는 받은 링크의 재공유가 아님을 UX에서 명확히 한다. 결과 페이지에서 자연스럽게 "내 비교 링크"를 만들도록 유도.

### 6.2 핵심 바이럴 요소

- **참여 의무감**: "친구가 기다리고 있음" → 안 하면 찝찝
- **대결 뉘앙스**: "{닉네임}님이 비교를 기다리고 있어요!" → 궁금증 자극
- **비교 욕구**: "내가 더 대중적일까?" → 궁금해서 참여
- **2차 생성**: 참여자가 자신의 비교 링크를 새로 만듦 → 받은 링크 재공유가 아닌 확산

## 7. 서버-FE 역할 분리

> BE 데이터 모델/엔티티 설계는 BE 팀이 자체 설계한다. 이 섹션은 FE 관점에서 서버와의 계약을 정의한다.

### 7.1 원칙: 서버는 숫자, FE는 매핑

서버는 원시 데이터(수치, 비율, 답변)만 리턴한다. 등급/캐릭터/문구/색상 등 모든 UI 매핑은 FE에서 처리한다. 스펙 변경 시 FE만 수정하면 되도록 한다.

| 항목        | 서버 리턴                    | FE 매핑                                       |
| ----------- | ---------------------------- | --------------------------------------------- |
| 케미        | 일치율 (숫자)                | 등급(S/A/B/C/D) + 타이틀 + 한줄평 + 3D 캐릭터 |
| 대중성      | 질문별 투표 비율             | 대중성 지수 계산 + 등급 + 캐릭터 + 문구       |
| 충격 포인트 | 질문별 투표 비율 + 유저 답변 | 가장 극단적 차이 선별 + 코멘트                |
| 가치관 지도 | 질문별 축 배정 + 유저 답변   | 좌표 계산 + 4분면 배치                        |
| 그룹 어워드 | 멤버별 답변 + 투표 비율      | 어워드 산출 + 칭호 + 한줄평                   |
| 스토리텔링  | 일치/불일치 질문 목록        | 요약 문구 매핑                                |

### 7.2 대중성 실시간 변동

대중성 수치는 다른 유저의 투표가 진행될수록 변동된다.

- 서버: 각 질문의 현재 옵션 A/B 투표 비율을 리턴
- FE: 비율 데이터 기반으로 대중성 지수 실시간 계산
- 결과 페이지 재방문 시 최신 비율 기준으로 재계산
- 대중성 등급/캐릭터/문구 매핑 데이터는 FE 상수로 관리

## 8. API 엔드포인트

### 8.1 번들 기본

| Method | Endpoint                           | 설명                              |
| ------ | ---------------------------------- | --------------------------------- |
| GET    | `/api/v1/bundles`                  | 번들 목록 (메인 피드용)           |
| GET    | `/api/v1/bundles/{slug}`           | 번들 상세 (인트로 페이지)         |
| GET    | `/api/v1/bundles/{slug}/elections` | 번들 질문 목록 (로그인 필수)      |
| POST   | `/api/v1/bundles/{slug}/answers`   | 답변 제출 → 세션 생성 + 완료 처리 |
| GET    | `/api/v1/bundles/{slug}/my-result` | 내 결과 조회                      |

### 8.2 비교 링크

| Method | Endpoint                                  | 설명                                              |
| ------ | ----------------------------------------- | ------------------------------------------------- |
| POST   | `/api/v1/bundles/{slug}/compare-links`    | 비교 링크 생성 (1:1 or 그룹)                      |
| GET    | `/api/v1/compare-links/{token}`           | 비교 링크 정보 조회 (링크 클릭 시)                |
| PATCH  | `/api/v1/compare-links/{token}`           | 비교 링크 수정 (그룹명, 최대인원 등, 생성자 전용) |
| POST   | `/api/v1/compare-links/{token}/join`      | 비교 링크에 참여 (번들 완료 후)                   |
| PATCH  | `/api/v1/compare-links/{token}/close`     | 그룹 마감 (생성자 전용)                           |
| PATCH  | `/api/v1/compare-links/{token}/reopen`    | 그룹 재오픈 (만료 기간 내, 생성자 전용)           |
| GET    | `/api/v1/bundles/{slug}/my-compare-links` | 내 비교 링크 목록 (참여한 것 + 생성한 것 구분)    |

### 8.3 비교 결과

| Method | Endpoint                                                 | 설명                    |
| ------ | -------------------------------------------------------- | ----------------------- |
| GET    | `/api/v1/compare-links/{token}/result?targetUserId={id}` | 1:1 비교 결과 (숫자만)  |
| GET    | `/api/v1/compare-links/{token}/group-result`             | 그룹 비교 결과 (숫자만) |

### 8.4 1:1 비교 결과 응답 구조

> 서버는 숫자/데이터만 리턴. 등급, 캐릭터, 문구, 스토리텔링 등 모든 매핑은 FE에서 처리.

```typescript
// 서버 응답 — 숫자만
interface CompareResult {
  bundleSlug: string;
  bundleTitle: string;
  totalQuestions: number;

  me: {
    nickname: string;
    answers: Array<{ electionId: string; selected: 'A' | 'B' }>;
  };

  target: {
    nickname: string;
    answers: Array<{ electionId: string; selected: 'A' | 'B' }>;
  };

  // 각 질문별 현재 투표 비율 (실시간 변동)
  questionStats: Array<{
    electionId: string;
    title: string;
    optionA: string;
    optionB: string;
    optionARate: number; // 0~100
    optionBRate: number; // 0~100
    totalVotes: number;
    axis: 'X' | 'Y' | null; // 가치관 지도용 축 배정 (null = 미배정)
  }>;

  matchCount: number; // 같은 답 개수
  matchRate: number; // 일치율 (0~100)
}

// FE에서 매핑하는 항목들 (FE 상수로 관리)
// - matchRate → 케미 등급 (S/A/B/C/D) + 타이틀 + 한줄평 + 3D 캐릭터
// - questionStats → 대중성 지수 계산 → 등급 + 캐릭터
// - questionStats → 충격 포인트 선별 (소수파/다수파 차이 가장 큰 질문)
// - questionStats → "같은 편/갈린 순간" 스토리텔링 문구
```

## 10. 어드민 관리 기능

### 10.1 번들 CRUD

| 항목               | 설명                                                            |
| ------------------ | --------------------------------------------------------------- |
| **번들 기본 정보** | 제목, 부제, 설명, 슬러그, 카테고리, 대표 이미지                 |
| **상태 관리**      | ACTIVE / CLOSED 전환 (번들은 만료 없음, 수동 CLOSED만 가능)     |
| **피드 노출 순서** | 싱글 피드 내 번들 카드 노출 우선순위 (숫자 지정, 낮을수록 먼저) |

### 10.2 질문 관리

| 항목                    | 설명                                        |
| ----------------------- | ------------------------------------------- |
| **질문 추가/수정/삭제** | 질문 텍스트, 옵션 A/B 텍스트                |
| **질문 순서**           | 드래그 또는 숫자로 순서 지정                |
| **질문 수 제한**        | 최소 5개, 최대 10개 — 범위 밖이면 저장 불가 |

> 이미 참여자가 있는 번들의 질문은 수정/삭제 불가. 새 번들로 생성해야 함.

### 10.3 가치관 지도 축 설정

| 항목               | 설명                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| **X축 라벨**       | 축 양쪽 끝 라벨 (예: "현실주의 ↔ 이상주의")                                 |
| **Y축 라벨**       | 축 양쪽 끝 라벨 (예: "개인 중심 ↔ 관계 중심")                               |
| **질문별 축 배정** | 각 질문을 X축 또는 Y축에 배정 (미배정도 가능). 옵션 A/B가 어느 방향인지 지정 |
| **4분면 라벨**     | 각 분면에 테마 맞춤 라벨 (예: "현실적 개인주의자", "이상적 관계중심파" 등)   |

### 10.4 케미 등급 맞춤 문구

| 항목                 | 설명                                      |
| -------------------- | ----------------------------------------- |
| **등급별 맞춤 문구** | S/A/B/C/D 각 등급에 대한 테마 맞춤 한줄평 |
| **미설정 시**        | 기본 문구(섹션 5.1) 사용                  |

### 10.5 스토리텔링 문구

| 항목                      | 설명                             |
| ------------------------- | -------------------------------- |
| **"같은 편" 요약 템플릿** | 같은 답 조합에 대한 요약 문구    |
| **"갈린 순간" 코멘트**    | 다른 답 조합에 대한 코멘트 문구  |
| **충격 포인트 코멘트**    | 소수파/다수파 조합별 재미 코멘트 |

> 스토리텔링 문구는 선택 사항. 미설정 시 FE에서 기본 템플릿("N개의 질문에서 같은 답을 골랐어요")으로 대체.

### 10.6 어드민 관리 요약

```
[어드민 번들 관리 페이지]
  │
  ├─ [번들 목록] — 상태, 참여자 수, 생성일 표시
  │
  └─ [번들 상세 편집]
      ├─ 기본 정보 (제목, 부제, 설명, 슬러그, 카테고리, 이미지)

      └─ 피드 노출 설정 (순서, 상태)
```

## 11. 단계별 구현 제안

### Phase 1: 번들 MVP (4/1 ~ 4/20, 3주)

> 목표: "연애 가치관 테스트" 번들 1개가 완전히 동작하는 MVP

**MVP 필수 기능:**

- 번들 CRUD (어드민)
- 번들 인트로 → 순차 질문(5개) → 내 결과 확인
- 메인 피드 내 번들 카드 노출 (싱글 피드 중간 삽입)
- 1:1 비교 초대 링크 생성 + 카카오톡 공유
- 초대받은 사람이 같은 번들 풀기
- 1:1 비교 결과 카드 (케미 등급, 충격 포인트, 대중성 비교, 스토리텔링)
- 대중성 지수 계산 (번들 참여자 모수 기준, FE 실시간 계산)

**MVP에서 빼는 것:**

- 그룹 비교 (3인+) → Phase 2
- 위클리 HOT 자동 큐레이션 → Phase 3
- 푸시 알림 → Phase 3
- 비교 이력 관리 페이지 → Phase 3

### Phase 2: 그룹 비교 + 시딩 (4/21~)

> 목표: 첫 500명 유저 확보, 2차 공유 발생 확인

- 그룹 링크 생성 (이름 + 인원 설정)
- 그룹 비교 결과 (통계, 답변 분포, 어워드)
- 가치관 지도 (클러스터링 점도표)
- 케미 네트워크 시각화
- 그룹 마감 기능
- 지인 네트워크 시딩 → 커뮤니티 시딩 (비교 카드를 콘텐츠로)

### Phase 3: 검증 + 고도화 (5/5~)

> 목표: 바이럴 검증 → 2번째 번들 출시 → 광고 부스팅

- 내 번들/비교 관리 페이지
- 그룹 간 내 포지션 비교
- 2번째 번들("결혼 가치관") + 3번째 번들("직장인 생존") 출시
- 푸시 알림 ("비교 결과가 도착했어요!")
- 위클리 HOT 자동 큐레이션
- 인스타 광고 부스팅 (월 20~30만원, 비교 카드를 소재로)

### Phase 2 시딩 종료 시점 (5/4) — Go/No-Go 판단

| 지표                 | 목표      | 미달 시 대응                           |
| -------------------- | --------- | -------------------------------------- |
| 번들 완료율          | 70% 이상  | UX 개선 (질문 수 줄이기, 진행 바 등)   |
