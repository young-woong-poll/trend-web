# HotPick 서비스 기획서

> **최종 업데이트**: 2026-03-01
> **작성 목적**: AI Agent가 HotPick의 전체 맥락을 이해하고 개발/기획 작업에 참여할 수 있도록 정리한 문서

---

## 1. 서비스 개요

### 1.1 서비스 정의

HotPick은 **"애매한 고민을 대중 투표로 해결하는 실용 도구형 플랫폼"**이다.
유저가 일상에서 마주하는 애매한 선택지에 대해 투표하고, 대중의 답을 숫자(퍼센티지)로 즉시 확인할 수 있다.

### 1.2 핵심 가치 제안

- **속도**: 탭 한 번, 1초 만에 투표 완료
- **규모**: 수천 명의 정량적 대중 의견 확인 (커뮤니티 댓글 3~5개와의 차별점)
- **직관성**: 배경 설명 없이 3초 안에 한쪽을 고를 수 있는 콘텐츠

### 1.3 한 줄 포지셔닝

- **토스**: "이체를 공인인증서 없이 30초 만에"
- **당근**: "중고거래를 동네 이웃과 안전하게"
- **HotPick**: "대중의 답을 탭 한 번에 숫자로"

### 1.4 타겟 유저

- **주 타겟**: 트렌드에 민감한 20~40대 한국 청년
- **유입 채널**: 에펨코리아, 블라인드, 에브리타임, 인스타그램, 카카오톡 공유

## 2. 브랜딩

### 2.1 슬로건

- **메인 슬로건**: "애매하면 핫픽" (조건 + 서비스명 공식: "배고프면 배민"과 동일 구조)
- **서브카피**: "정하고 가자, 모두의 답으로"
- **슬로건 후보** (확정 전 검토 중):
  - "고르면 보인다" / "골라야 보인다"
  - "넌 어느 쪽?"
  - "모두의 답"
  - "애매한 거? 정해드립니다"

### 2.2 톤앤매너

- **디자인**: 다크 테마 + 오렌지-레드(#FF4500)에서 마젠타(#FF00FF) 그라디언트 + 네온 옐로우 포인트
- **분위기**: 활기찬 나이트클럽 느낌. 가볍지만 촌스럽지 않은 톤
- **카피 톤**: "궁금하다 → 확인한다 → 공유한다" 흐름. 전투적 카피("싸운다") 지양
- **로고**: 불꽃 실루엣 안에 체크마크. 오렌지→마젠타 리니어 그라디언트

### 2.3 서비스가 해결하는 문제

**기존 방식 (커뮤니티):**

- 글을 써야 함 (5분)
- 배경을 설명해야 함
- 댓글이 달릴 때까지 기다려야 함 (수십 분)
- 3~5개 의견이 전부이며, 이것이 대중 의견인지 알 수 없음

**HotPick 방식:**

- 탭 한 번 (1초)
- 배경 설명 불필요
- 즉시 결과 확인
- 수천 명의 정량적 데이터 (예: "73% vs 27%, 참여자 2,400명")

> **핵심 차별점**: "내 고민 해결"이 아니라 **"보편적 상황에 대한 대중 의견 확인"**.
> 커뮤니티는 "조언을 구하러" 가고, HotPick은 "내 생각이 다수인지 확인하러" 온다.

## 3. 콘텐츠 구조

### 3.1 콘텐츠 타입

HotPick은 두 가지 콘텐츠 타입을 운영한다.

#### 싱글 핫픽 (Single HotPick) — 리텐션 엔진

- **역할**: 매일 피드에서 가볍게 투표하고 결과를 보는 일상적 루틴
- **UX**: 메인 피드에서 바로 투표 가능 (상세 페이지 진입 불필요)
- **투표 형식**: 이지선다 (A vs B)
- **결과**: 투표 즉시 퍼센티지 바로 결과 확인
- **재투표**: 불가. 결과를 보고 투표를 바꾸면 데이터 왜곡이 발생하므로 허용하지 않음
  - 실수 방지: 투표 직후 1~2초 "투표 완료" 토스트에 "취소" 버튼 (Gmail 실행취소 패턴)
  - 아쉬움 해소: 댓글 기능으로 의견 표출 유도

#### 번들 핫픽 (Bundle HotPick) — 바이럴 엔진

- **역할**: 결과 카드를 공유해서 새로운 유저를 데려오는 바이럴 루프
- **UX**: 상세 페이지에 진입 → 5개 투표를 순차적으로 진행 → 최종 결과 카드 제공
- **투표 형식**: 테마로 묶인 5개의 이지선다
- **결과**: 유형 결과 카드 (캐릭터 이미지 + 대중성 지수 + 해시태그)
- **공유**: 결과 카드를 캡처해서 인스타 스토리, 카카오톡 등으로 공유
- **재투표**: 가능. MBTI 테스트처럼 다른 선택지로 다시 해보는 것이 자연스러운 경험
- **빈도**: 운영자 큐레이션 콘텐츠. 피드에서 싱글 7~10개에 번들 1개 비율로 배치

### 3.2 피드 구조

- **메인 피드**: 싱글 핫픽이 주를 이룸. 스크롤하며 가볍게 하나씩 투표
- **번들 배치**: 싱글 7~10개에 번들 1개 비율. 인스타 광고처럼 간간이 등장하는 "특별 콘텐츠" 느낌
- **싱글과 번들의 투표 데이터는 분리**: 같은 주제라도 각각 독립적으로 집계. 운영자가 등록 시 중복 방지를 수동 관리

### 3.3 콘텐츠 가이드라인

#### 좋은 싱글 핫픽의 기준 — "3초 룰"

주제를 읽고 3초 안에 한쪽을 고를 수 있어야 한다.

1. **배경 설명 없이 상황이 그려져야 함**
   - ✅ "연인이 전 애인 사진 안 지우면?"
   - ❌ "3년 사귄 여자친구가 전 남친이랑 같은 동네 사는데 전 애인 사진을 안 지우면?" (배경이 특수 → 커뮤니티 영역)
2. **선택지가 대등해야 함**
   - ✅ "축의금 5만원 vs 10만원" (진짜 갈림)
   - ❌ "부모님 말 잘 들어야 한다 vs 안 들어도 된다" (정답이 뻔함)
3. **결과가 궁금해야 함**
   - 50:50에 가까울 것 같은 주제가 가장 매력적
   - 80:20 예상 주제는 투표 동기가 약함

#### 번들 핫픽의 기준

- 5개 투표가 하나의 테마로 묶임
- 개별 질문의 긴장감보다 **테마의 재미와 결과의 공유 욕구**가 중요
- 결과를 캡처해서 SNS에 올리고 싶게 만드는 게 핵심

#### 콘텐츠 기피 기준

- 정치, 종교, 특정 집단 혐오로 이어질 수 있는 주제 금지
- 바이럴은 되지만 브랜드를 태워먹는 콘텐츠 차단
- UGC 전환 시에도 이 기준이 적용됨

### 3.4 콘텐츠 3가지 층위

1. **"정답이 궁금한" 고민형** — 리텐션 핵심
   - "썸 타는 사람한테 먼저 연락하면 약해 보일까?", "면접에서 연봉 얼마 불러야 해?"
   - 유저가 결과를 보고 "아 70%가 거절해도 된다고 하네, 나만 고민한 게 아니었구나"를 느끼는 순간 가치가 생김
2. **"내 성향이 궁금한" 논란형** — 바이럴 포텐셜
   - "전 애인 사진 지워야 함 vs 무슨 상관", "홍명보 vs 외국감독"
   - 정답이 없고 성향 차이. 댓글과 공유 동기가 강함
3. **"시의성 있는" 이슈형** — 신규 유입용
   - 월드컵, 선거, 연예인 사건 등 지금 핫한 이슈
   - 타이밍이 생명. 수명이 짧지만 터질 때 확 터짐

## 4. 생애주기별 콘텐츠 전략

> 개인화 없이도 "이거 내 얘기잖아" 느끼게 만드는 전략.
> 생애주기별 공통 고민을 뽑아서 피드에 적절히 배치하면, 타겟 연령대 누구든 스크롤 3~4번 안에 자기 고민을 만나게 됨.

### 4.1 피드 배치 비율

| 연령대                        | 비율 | 핵심 키워드                           |
| ----------------------------- | ---- | ------------------------------------- |
| 20대 초반 (대학생~사회초년생) | 15%  | 소개팅, 취업, 자취, 첫 월급           |
| 20대 후반 (직장 적응기)       | 25%  | 칼퇴, 이직, 동거, 월세 vs 전세        |
| 30대 초반 (결혼·독립기)       | 25%  | 결혼, 혼수, 신혼집, 시댁              |
| 30대 후반 (육아·자산형성기)   | 20%  | 아이, 사교육, 아파트 갈아타기, 창업   |
| 40대 (안정·설계기)            | 15%  | 자산배분, 조기은퇴, 부모님 용돈, 탈모 |

### 4.2 생애주기별 대표 주제

#### 20대 초반

- 연애: 썸 타는 사람한테 먼저 연락? vs 기다리기 / 소개팅 첫 만남 커피 vs 밥
- 진로: 대기업 vs 스타트업 / 전공 살리기 vs 하고 싶은 거
- 돈: 첫 월급 부모님 드리기 vs 내가 쓰기 / 적금 vs 주식
- 생활: 자취 vs 본가 / 친구 축의금 3만원 vs 5만원

#### 20대 후반

- 직장: 칼퇴 vs 눈치퇴 / 연봉 300 올려주는 이직 감? vs 안 감?
- 연애: 결혼 전제 아닌 연애 괜찮음? vs 시간낭비 / 연인이랑 동거 찬성 vs 반대
- 돈: 월세 vs 전세 / 차 사야 함? vs 대중교통 / 청약 넣어야 함?

#### 30대 초반

- 결혼: 결혼 해야 함? vs 안 해도 됨? / 신혼집 매매 vs 전세 / 혼수 각자 vs 반반
- 직장: 이직 vs 현 직장 승진 노리기 / 연봉 vs 워라밸
- 돈: 주식 vs 부동산 / 신혼집 영끌 vs 여유있게

#### 30대 후반

- 육아: 아이 가져야 함? vs 딩크 / 사교육 시켜야 함? vs 안 시켜도 됨?
- 직장: 안정적 직장 유지 vs 창업 도전 / 40대 전 이직 vs 늦었다
- 건강: 헬스 vs 러닝 / 아침 운동 vs 저녁 운동

#### 40대

- 자산: 부동산 추가 매수 vs 금융자산 / 조기은퇴 가능? vs 불가능?
- 가정: 아이 사립 vs 공립 / 부모님 용돈 얼마?
- 건강: 허리 디스크 수술 vs 보존치료 / 탈모 치료 vs 자연스럽게

### 4.3 전 연령대 공통 (피드 뼈대)

연애·돈·직장은 전 연령대 공통 관심사이므로 피드의 뼈대를 구성.
결혼·육아·건강은 연령대별 특화 콘텐츠로 사이사이 배치.

## 6. 기술 스펙

### 6.1 기술 스택

- **프론트엔드**: Next.js 14+ (App Router), TypeScript (strict mode)
- **스타일링**: SCSS Modules, 다크 테마 기반
- **상태관리**: React Query (TanStack Query v5)
- **애니메이션**: Framer Motion
- **API 타입**: Orval (OpenAPI → 자동 생성)
- **테스트**: Playwright (E2E) + MSW (Mock)
- **분석**: Google Analytics (GA4)
- **SEO**: 구조화 데이터 (JSON-LD), 사이트맵, OG 이미지

### 6.2 투표 시스템 (현재 구현 기준)

#### 사용자 식별 — TKUID

- **식별자**: UUID v4, localStorage에 `hp_tkuid` 키로 저장
- **생성 시점**: 사이트 최초 접속 시 자동 생성
- **전달 방식**: `x-tku-id` HTTP 요청 헤더
- **용도**: 투표 중복 방지, 댓글 좋아요 중복 방지, 투표/좋아요 상태 조회
- **소실 시**: 새 UUID 생성 → 이전 투표 이력 연결 불가, 새 사용자로 취급

#### 싱글 핫픽 — 인라인 투표

- **투표 API**: `POST /api/v1/hotpicks/{slug}/votes` — `{ electionItemId }` + `x-tku-id` 헤더
- **중복 방지**: 서버에서 TKUID + hotpickId 조합 중복 체크. 동일 조합이면 409 응답 (응답 본문에 현재 투표 상태 포함)
- **Optimistic Update**: 투표 클릭 즉시 UI 업데이트 → API 성공 시 실제 데이터로 교체, 실패 시 롤백
- **재투표**: 불가. 결과 확인 후 투표 변경은 허용하지 않음 (데이터 왜곡 방지)

#### 번들 핫픽 — ⚠️ BE 미구현

- FE 컴포넌트 존재하나 BE API 미구현 상태
- 투표 시도 시 "BUNDLE 투표는 준비 중입니다" 에러 표시
- Admin에서 BUNDLE 타입 생성 비활성화

#### 투표 데이터 분리 원칙

- 싱글과 번들의 투표 데이터는 서로 독립적으로 집계
- 같은 주제가 싱글과 번들에 동시에 존재할 수 있으나, 투표 데이터는 각각 별도
- 기능적 분리가 아닌 운영적 분리: 관리자가 등록 시 싱글/번들 간 동일 선거를 중복 등록하지 않도록 주의
- 서버 관점: 선거(Election)와 핫픽(HotPick)은 별도 도메인

#### 프리미엄 기능 (로그인 시스템 도입 후)

- 투표 변경: "하루 3회 투표 변경" 같은 제한으로 유료 전환 유인
- userId 기반 엄격한 1인 1표 적용

## 7. 성장 전략

### 7.1 전략 방향 — "논란 30% 유입, 고민 70% 리텐션"

- **시의성 이슈 + 논란 콘텐츠**: 신규 유저 유입용 (30%)
- **고민 해결 콘텐츠**: 리텐션 및 일상적 사용 (70%)

### 7.2 유저 여정 (바이럴 루프)

```
인스타/카톡에서 친구의 번들 결과 카드 보기
→ "나도 해볼까?" → 번들 참여
→ 결과 공유 (카카오톡, 인스타 스토리)
→ 그 사이 싱글 핫픽도 몇 개 투표
→ 다음날 또 들어와서 싱글 투표
→ 반복
```

번들이 유저를 데려오고, 싱글이 유저를 붙잡는 구조.

### 7.3 초기 성장 전략

#### 우선순위 (리소스 = 1인 개발)

1. **킬러 번들 콘텐츠 제작** → 바이럴 가능한 번들 1개에 올인
2. **커뮤니티 시딩** → 이미지(워터마크 포함)로 시딩. 직접 링크 절대 금지
3. **유입 유저 → 싱글 경험 동선 설계** → 번들로 들어온 유저가 싱글도 투표하게
4. **SEO** → 병행 (네이버 블로그에 후기 글 미리 작성)

#### 커뮤니티 바이럴 원칙

- **직접 링크 금지**: 홍보글로 신고당하고 계정 밴 위험
- **이미지 시딩**: 번들 결과 캡처 이미지를 "순수 참여 후기"처럼 올림. 이미지 안 워터마크로 유입 유도
- **검색으로 연결**: 워터마크 본 사람이 "핫픽" 검색 → 네이버 블로그/SEO로 랜딩
- **타사 브랜드명 사용 금지**: "블라인드", "에펨코리아" 등 직접 이름 사용 시 상표권 침해 및 커뮤니티 반발 위험
  - 대안: "직장인 익명 커뮤니티에서 3만 명이 싸운 그 논란" (카테고리로 표현)

#### 카카오톡 공유 최적화

- 번들 결과 카드에 "친구한테 공유하기" 버튼
- OG 태그 매력적 세팅: "나는 '현실주의 연애인'이래 ㅋㅋ 너도 해봐"

#### 인스타그램 스토리·릴스

- 번들 결과 카드를 인스타 스토리 사이즈로 제작
- 유저가 결과를 스토리에 올리면 팔로워 → HotPick 유입

### 7.4 오프라인 마케팅 — "핫픽맨이 간다"

#### 컨셉

가면을 쓴 캐릭터 "핫픽맨"이 22인치 태블릿을 들고 특정 지역에서 현장 투표를 받으며, 그 과정을 숏폼 영상으로 촬영해 인스타 릴스, 유튜브 쇼츠, 틱톡으로 배포.

#### 핵심 원칙: "다가가지 말고 끌어당겨라"

- 핫픽맨은 말 안 하고 서 있기만 함
- 태블릿 화면에 "카카오 vs 네이버, 판교는 어느 쪽?" 크게 띄움
- 가면 + 태블릿 비주얼이 호기심을 유발 → 사람들이 스스로 다가옴
- 다가온 사람한테만 "아무거나 탭 한번만요" 정도
- 이름/번호 수집 없음. 탭 한 번이면 끝

#### 장소 × 주제 매칭

| 장소   | 주제 예시                 |
| ------ | ------------------------- |
| 판교역 | 카카오 vs 네이버          |
| 강남역 | 월세 vs 전세              |
| 대학로 | 대기업 vs 스타트업        |
| 여의도 | 주식 vs 부동산            |
| 홍대   | 소개팅 첫 만남 커피 vs 밥 |

#### 영상 구조

1. 오프닝 3초: "판교 직장인 100명한테 물어봤다" 자막 + 핫픽맨 등장
2. 중간: 재밌는 현장 반응 편집
3. 마지막: "현장 결과 62:38, 근데 온라인에서는?" → HotPick 사이트 투표 결과 보여주기
4. 현장 vs 온라인 결과 차이 = 시청자 투표 동기 부여

#### 시리즈화

- "핫픽맨이 간다 — 판교편", "핫픽맨이 간다 — 강남편" 등
- 영상 댓글에서 "다음에 이 주제로 해주세요" → UGC 콘텐츠 기획 소스

#### 핫픽맨 장비

- **가면**: 로고 기반 디자인. 3D 프린팅 또는 EVA 폼 제작 (외주 추천: 크몽, 15~30만원). 대안으로 무지 가면 + 로고 비닐 래핑 스티커 (5만원 이내)
- **의상**: 올블랙 후디 + 블랙 팬츠. 후디 가슴에 로고, 등판에 "애매하면 핫픽" 또는 URL. 장갑 한쪽 오렌지 / 한쪽 마젠타 (A/B 선택지 상징)
- **태블릿**: 22인치. 웹 전용 태블릿 페이지로 개발 (Electron 불필요)

#### 촬영 주의사항

- 초상권: 투표 참여자 얼굴 노출 시 동의 필요. 태블릿 화면 + 손만 촬영하거나, 촬영 동의 팻말 설치

### 7.5 더미 데이터에 대한 입장

- **사용하지 않음**: "대중의 답을 숫자로 보여준다"가 핵심 가치인 서비스에서 숫자가 가짜면 존재 이유가 무너짐
- **대안**: 초기에 투표수를 아예 안 보여주거나, 솔직하게 작은 숫자를 보여주되 "지금 참여하면 초기 멤버" 프레이밍

### 7.6 OG 태그 / SEO 문구

#### 현재 구현된 문구

- **메인 OG 타이틀**: "애매하면? 핫픽"
- **메인 OG 설명**: "애매한 고민, 사람들의 생각을 확인하세요!"
- **상세 OG 타이틀**: `{투표 제목}` (예: "연인이 전 애인 사진 안 지우면?")
- **상세 OG 설명**: `{선택지A} vs {선택지B} - 지금 바로 투표하세요!`
- **OG 이미지**: 동적 생성. 다크 카드에 질문 + A/B 선택지 + 참여자 수 표시
- **구조화 데이터**: JSON-LD `Question` + `suggestedAnswer` 스키마

#### 향후 시딩/공유용 문구 후보

**숫자 임팩트형:**
- "10만 명이 갈렸던 그 질문, 너는 어느 쪽?"
- "댓글 3,000개 달렸던 역대급 논쟁, 투표로 끝내자"

**커뮤니티 카테고리형 (타사 브랜드명 미사용):**
- "직장인 익명 커뮤니티 역대 1위 논쟁"
- "20대 남성 커뮤니티에서 난리났던 그 주제"

**FOMO 자극형:**
- "이미 2,400명이 답 정했는데, 너만 아직"
- "결과 보고 놀란 사람 속출 중"

| **MVP 정신**                     | 운영으로 통제 가능한 건 기능으로 만들지 않음. 최소 리소스로 최대 검증 |
| **데이터 정직성**                | 더미 데이터 미사용. 투표 수치의 신뢰가 서비스 존재 이유               |

## 10. 용어 사전

| 용어                | 정의                                                             |
| ------------------- | ---------------------------------------------------------------- |
| **싱글 핫픽**       | 메인 피드에서 바로 투표할 수 있는 개별 이지선다 투표             |
| **번들 핫픽**       | 테마로 묶인 5개 투표 세트. 완료 시 유형 결과 카드 제공 (BE 미구현) |
| **선거 (Election)** | 서버 도메인에서의 투표 단위. 하나의 질문 + 선택지 세트           |
| **핫픽 (HotPick)**  | 서비스 도메인에서의 콘텐츠 단위. 싱글 또는 번들 타입             |
| **TKUID**           | 익명 사용자 식별용 UUID. localStorage `hp_tkuid`에 저장          |
| **Slug**            | 핫픽의 URL용 고유 식별자 (예: chicken-2024)                      |
| **VoteType**        | FE에서 추론하는 투표 표시 방식. IMAGE(옵션별 이미지) 또는 TEXT    |
| **TopComment**      | 각 핫픽의 가장 좋아요가 많은 댓글. 피드 카드 미리보기             |
| **핫픽맨**          | 오프라인 마케팅 캐릭터. 가면 + 태블릿으로 현장 투표 수집         |
| **3초 룰**          | 좋은 싱글 핫픽 콘텐츠의 기준. 3초 안에 선택 가능해야 함          |
| **바이럴 루프**     | 번들 결과 공유 → 새 유저 유입 → 싱글 리텐션 → 다시 번들 공유     |
