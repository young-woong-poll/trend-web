# HotPick 선거 시스템 내재화 설계서

> 선거(Election) CRUD를 HotPick 서비스로 이전하고, P0 기능을 수용하는 새로운 구조 설계
> 작성일: 2025-02-13

---

## 1. 배경

### 1.1 현재 구조

```
console.votebox.kr (외부)              hotpick-api.votebox.kr (내부)
┌────────────────────────────┐         ┌────────────────────────────────┐
│ 선거 생성/수정/삭제         │         │ HotPick(묶음) 생성             │
│ 옵션 관리                   │  ─ID─▶ │   └ electionIds: string[]      │
│ 투표/결과 집계              │         │ 투표/결과 조회                 │
└────────────────────────────┘         └────────────────────────────────┘
```

Admin에서 핫픽을 생성할 때, 선거 ID를 console에서 복사해 입력하는 수동 프로세스가 존재한다.

### 1.2 문제점

| 문제                  | 설명                                                                                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **이중 관리**         | console에서 선거 생성 → ID 복사 → hotpick Admin에 붙여넣기                                                                                    |
| **인터페이스 불일치** | console의 `ElectionDetail`에 hotpick에서 불필요한 필드 다수 (`description`, `kind`, `allowMultipleVotes`, `startTime/endTime`, `isUnlimited`) |
| **확장성 제약**       | console 선거는 `Option.imageUrl` 필수, 옵션 2개 고정 → P0 기능(텍스트 투표, 다중 선택지, Single) 수용 불가                                    |
| **개발 속도 저하**    | 선거 구조 변경 시 console BE → hotpick BE → FE 3단계 의존                                                                                     |

### 1.3 결정 사항

**선거 CRUD를 hotpick 서비스로 이전한다.** HotPick에 최적화된 선거 인터페이스를 새로 정의하고, Admin에서 선거를 직접 생성/관리한다.

## 2. 용어 정의

| 용어           | 코드     | 설명                                                      |
| -------------- | -------- | --------------------------------------------------------- |
| **Election**   | —        | 하나의 투표 질문 (옵션 2~4개)                             |
| **HotPick**    | —        | Election을 묶어 사용자에게 전시하는 단위                  |
| **BUNDLE**     | `BUNDLE` | 기존 트렌드 — Election 2개 이상 묶음, 결과 유형 분류 포함 |
| **SINGLE**     | `SINGLE` | 단일 투표 — Election 1개로 독립 운영, 결과 유형 없음      |
| **IMAGE 투표** | `IMAGE`  | 옵션마다 이미지 + 텍스트 (기존 방식)                      |
| **TEXT 투표**  | `TEXT`   | 메인 이미지 1장 + 옵션은 텍스트만 (신규)                  |

## 4. 엔티티 설계

### 4.1 Election (선거)

```typescript
/**
 * 투표 UI 유형
 */
type VoteType = 'IMAGE' | 'TEXT';

/**
 * 선거 상태
 */
type ElectionStatus = 'OPEN' | 'CLOSED';

/**
 * 선거 옵션 (후보)
 */
interface ElectionOption {
  id: string;
  title: string; // 옵션 텍스트 (필수)
  imageUrl?: string; // IMAGE 유형일 때 필수, TEXT 유형일 때 불필요
  order: number; // 옵션 순서 (0부터)
}

/**
 * HotPick 선거 엔티티
 */
interface Election {
  id: string;
  title: string; // 질문 텍스트
  voteType: VoteType; // 투표 UI 유형
  mainImageUrl?: string; // TEXT 유형일 때 메인 이미지
  options: ElectionOption[]; // 2~4개 옵션
  status: ElectionStatus; // OPEN | CLOSED
  createdAt: string;
  updatedAt: string;
}
```

### 4.2 console `ElectionDetail` 대비 변경점

| console (기존)           | HotPick (신규)          | 이유                               |
| ------------------------ | ----------------------- | ---------------------------------- |
| `description`            | **제거**                | HotPick에서 미사용                 |
| `kind: 'DEFAULT'`        | **제거**                | 단일 종류만 존재                   |
| `allowMultipleVotes`     | **제거**                | 항상 단일 투표                     |
| `startTime / endTime`    | **제거**                | HotPick 레벨의 `deadline`으로 대체 |
| `isUnlimited`            | **제거**                | `deadline` 유무로 판단             |
| `Option.description`     | **제거**                | UI에서 미사용                      |
| `Option.imageUrl` (필수) | `imageUrl?` (선택)      | TEXT 유형 지원                     |
| —                        | `voteType` **추가**     | IMAGE / TEXT 분기                  |
| —                        | `mainImageUrl` **추가** | TEXT 유형 메인 이미지              |
| —                        | `Option.order` **추가** | 옵션 순서 관리                     |

### 4.3 HotPick (핫픽)

```typescript
/**
 * 핫픽 유형
 */
type HotpickType = 'BUNDLE' | 'SINGLE';

/**
 * 카테고리 코드 (DB 10개)
 * - 화면 필터에는 6개만 노출: 연애/결혼, 재테크, 직장, 스포츠, 음식, 트렌드
 */
type CategoryCode =
  | 'LOVE'
  | 'MARRIAGE'
  | 'FINANCE'
  | 'WORK'
  | 'SPORTS'
  | 'FOOD'
  | 'GAME'
  | 'CAR'
  | 'HEALTH'
  | 'TREND';

/**
 * HotPick 엔티티 (확장)
 */
interface HotPick {
  id: number;
  alias: string;
  title: string;
  label?: string;
  type: HotpickType; // 🆕 BUNDLE | SINGLE
  imageUrls?: string[]; // BUNDLE: 커버 이미지 1장 이상
  categoryCode?: CategoryCode; // 🆕 카테고리
  deadline?: string; // 🆕 마감일시 (null이면 상시)
  status: 'OPEN' | 'CLOSED'; // 🆕 마감 상태
  electionIds: string[]; // BUNDLE: 2개 이상, SINGLE: 1개
  meta?: HotpickMeta; // BUNDLE 전용 (결과 유형)
  visible: boolean;
  totalVotes: number; // 🆕 총 투표 수
  createdAt: string;
}
```

### 4.4 엔티티 관계도

```
┌─────────────────────────────────────────────────────┐
│                    Category                          │
│  (FOOD, ENTERTAINMENT, SPORTS, ...)                 │
└──────────────────────┬──────────────────────────────┘
                       │ 1:N
┌──────────────────────▼──────────────────────────────┐
│                   HotPick                            │
│  type: BUNDLE | SINGLE                               │
│  deadline?: datetime                                 │
│  status: OPEN | CLOSED                               │
│  categoryCode?: CategoryCode                         │
├──────────────────────┬──────────────────────────────┤
│  BUNDLE (묶음 투표)   │  SINGLE (단일 투표)          │
│  - Election 2개 이상  │  - Election 1개              │
│  - 커버이미지 1장 이상│  - 카드 형태 노출            │
│  - 결과 유형 분류     │  - 결과 유형 없음            │
└──────────────────────┼──────────────────────────────┘
                       │ 1:N
┌──────────────────────▼──────────────────────────────┐
│                   Election                           │
│  voteType: IMAGE | TEXT                              │
│  mainImageUrl?: string (TEXT용)                      │
│  options: ElectionOption[] (2~4개)                   │
└──────────────────────────────────────────────────────┘
```

## 5. Admin 관리 구조

### 5.1 페이지 구조

```
/admin
├── /election                         ← 🆕 선거 관리
│   ├── page.tsx                      (선거 목록)
│   ├── /create/page.tsx              (선거 생성)
│   └── /edit/[electionId]/page.tsx   (선거 수정)
│
├── /hotpick                          ← 기존 trend → hotpick 통합
│   ├── page.tsx                      (핫픽 목록: BUNDLE + SINGLE)
│   ├── /create/page.tsx              (핫픽 생성)
│   └── /edit/[hotpickId]/page.tsx    (핫픽 수정)
│
└── layout.tsx                        (기존 유지)
```

### 5.2 기존 vs 변경 후 관리 플로우

**현재 (console 의존):**

```
1. console.votebox.kr 로그인
2. 선거 생성 (제목, 설명, 옵션 2개 + 이미지 각각)
3. 선거 ID 복사
4. hotpick Admin으로 이동
5. 트렌드 생성 → 선거 ID 여러 개 붙여넣기
6. 발행
```

**변경 후 (HotPick 통합):**

```
1. hotpick Admin → /admin/election/create
   선거 생성 (제목, 투표유형, 옵션 입력)
2. hotpick Admin → /admin/hotpick/create
   핫픽 생성 → 타입 선택 (BUNDLE/SINGLE)
   → 선거 목록에서 검색 + 선택
3. 발행
```

## 7. 마감 시스템

- HotPick에 `deadline` 필드 추가 (Election이 아닌 HotPick 레벨에서 관리)
- `deadline`이 null이면 상시 투표 가능
- 마감일 도래 시 서버 스케줄러가 `status`를 `OPEN` → `CLOSED`로 전환
- 마감된 HotPick은 투표 불가, 결과 열람만 가능

**FE 표시 규칙:**

| 조건          | 표시                          |
| ------------- | ----------------------------- |
| D-3 이내      | 마감임박 배지 (🔥)            |
| D-1 이내      | 카운트다운 (시:분:초)         |
| 마감 후       | "마감" 배지, 투표 버튼 비활성 |
| deadline 없음 | 마감 관련 UI 미표시           |

## 9. 구현 순서

### Phase 1: 기반 작업

> 선거 관리 독립 + Admin 체계 구축

1. **타입 수정** — `election.ts`, `hotpick.ts` 인터페이스 업데이트
2. **Admin Election CRUD** — 선거 목록/생성/수정 페이지 개발
3. **핫픽 폼 선거 연결 방식 변경** — ID 입력 → 목록 검색/선택

### Phase 2: P0 기능 반영

> 투표 유형 다양화 + 탐색 경험 개선

4. **TEXT 투표 유형** — VoteCard, VoteOptionCard 분기 렌더링
5. **카테고리 필터** — Main 페이지 카테고리 칩 UI
6. **마감 시스템** — 카운트다운, 마감 배지, 비활성 처리
7. **SINGLE 탭 및 카드** — Main 페이지 탭 분리, SingleCard 컴포넌트

### Phase 3: 마이그레이션

> 기존 console 의존 완전 제거

8. **기존 선거 데이터 마이그레이션** — BE 주도, console → hotpick DB
9. **기존 API 호출 경로 전환** — `/admin/api/v1/item/{itemId}` → `/admin/api/v1/election/{electionId}`
