> HotPick 벤치마킹 참고자료
> 작성일: 2025-02-11

## 1. 질문 구조 (Question Structure)

Polymarket의 질문은 3가지 형태로 구성된다.

### 1-1. Yes/No (이진 질문)

가장 기본적인 형태. 특정 이벤트의 발생 여부에 베팅한다.

- **구조**: YES 또는 NO 중 택 1
- **예시**: "비트코인이 2026년 6월까지 $100,000를 돌파할까?"
- **결과**: 발생 시 YES = $1, NO = $0 / 미발생 시 반대
- **특징**: Polymarket에서 가장 많은 비중을 차지하는 유형

### 1-2. Either/Or (양자택일)

두 개의 경쟁 옵션 중 하나를 선택한다.

- **구조**: 옵션 A vs 옵션 B
- **예시**: "Warriors vs Lakers — 누가 이길까?"
- **특징**: Yes/No와 구조적으로 동일하나, 프레이밍이 비교 형태
- **제한**: 멀티 아웃컴 마켓에서는 사용 불가 (단일 비교이므로)

### 1-3. Up/Down (방향성 질문)

특정 값이 기준점 이상/이하인지에 베팅한다.

- **구조**: 특정 수치 기준 상회/하회
- **예시**: "Warriors vs Lakers: O/U 229.5" (총 득점이 229.5 이상/이하)
- **키워드**: "crosses", "at least", "above", "below", "over/under"
- **특징**: NegRisk가 아님 — 여러 기준점이 동시에 충족될 수 있음

## 2. 마켓 유형 (Market Types)

### 2-1. Binary Market (이진 마켓)

- **정의**: 2가지 결과(YES/NO)만 존재하는 마켓
- **가격 원칙**: YES 가격 + NO 가격 = $1.00
- **예시**: "2025년 말까지 Tetranode의 트위터 팔로워가 10만을 넘길까? YES/NO"
- **정산**: 이벤트 발생 시 YES = $1, NO = $0
- **용도**: 단순한 예측, 스포츠 승패, 정치 이벤트

### 2-2. Categorical Market (카테고리컬 마켓)

- **정의**: 3개 이상의 옵션이 존재하며, 하나만 $1로 정산되는 마켓
- **예시**: "2025년 아이스크림 최다 판매 맛은? 초콜릿/바닐라/딸기/기타"
- **구조**: 각 옵션이 독립적인 YES/NO 바이너리로 운영
- **용도**: 선거 후보 예측, 수상자 예측, 순위 예측

### 2-3. Scalar Market (스칼라 마켓)

- **정의**: 결과가 연속적 수치 범위 내에서 결정되는 마켓
- **예시**: "스페인 차기 인구 조사 결과는? (4,700만~5,500만 범위)"
- **정산**: 실제 값이 범위 내 어디에 위치하는지에 따라 비례 정산
- **현재 상태**: Polymarket에서는 실질적으로 여러 개의 바이너리 질문으로 분해하여 운영
  - 예: "테슬라 주가 $200 돌파?", "$250 돌파?", "$300 돌파?" 각각 별도 마켓

## 3. 마켓 구조 (Market Structure)

### 3-1. Single-Outcome Market (단일 결과 마켓)

- 하나의 독립된 질문 = 하나의 마켓
- Yes/No, Either/Or, Up/Down 모든 질문 유형 사용 가능
- **예시**: "바이든이 임기를 마칠까?"

### 3-2. Multi-Outcome Market (복수 결과 마켓)

- 하나의 이벤트에 여러 관련 마켓이 묶여있는 구조
- **예시**: "Buccaneers vs Lions" 이벤트 하위에:
  - Moneyline (Either/Or): 누가 이기나?
  - Spread: 어느 팀이 스프레드 커버하나?
  - Over/Under: 총 득점 기준점 상회/하회?
  - Player Props: 특정 선수 개인 기록

#### 3-2a. Negative Risk (NegRisk) 마켓

- **정의**: 복수 결과 중 **오직 하나만** YES로 정산되는 구조
- **원칙**: 하나의 옵션에 YES 베팅 = 나머지 모든 옵션에 NO 베팅
- **모든 YES 가격의 합 ≈ $1.00**
- **예시**: "2028 대선 승자는?" → 트럼프/해리스/디샌티스/기타 중 1명만 당선
- **장점**: 자본 효율성 향상 (모든 옵션 구매 시 $1만 필요)
- **기술**: NO 포지션을 다른 마켓의 YES 포지션으로 전환(convert) 가능

#### 3-2b. Non-NegRisk 복수 결과 마켓

- **정의**: 복수 결과 중 **여러 개가 동시에** YES로 정산될 수 있는 구조
- **예시**: "2025년에 트럼프가 만날 인물은?" → 여러 인물을 만날 수 있음
- **방향성(Up/Down) 마켓**: 여러 기준점이 동시 충족 가능하므로 항상 Non-NegRisk

#### 3-2c. Augmented Negative Risk (증강 NegRisk)

- **정의**: NegRisk의 확장형. 사전에 명명되지 않은 결과가 추후 추가될 수 있는 구조
- **구조**: 명명된 옵션들 + 미명명 옵션들 + "기타(Other)" 옵션
- **특징**: 새로운 후보/옵션이 등장하면 미명명 슬롯을 활용해 추가
- **UI**: 미명명 옵션은 표시되지 않음
- **용도**: 정치 선거처럼 후보가 갑자기 등장할 수 있는 이벤트

## 4. 이벤트 그룹핑 (Event Grouping)

### 4-1. 단일 이벤트 — 단일 마켓

```
[이벤트] "바이든 임기 완수?"
  └── [마켓] YES / NO
```

### 4-2. 단일 이벤트 — 복수 마켓

```
[이벤트] "2028 미국 대선"
  ├── [마켓] 대선 승자는? (NegRisk: 트럼프/해리스/디샌티스/...)
  ├── [마켓] 민주당 후보는? (NegRisk)
  ├── [마켓] 공화당 후보는? (NegRisk)
  └── [마켓] 투표율 60% 이상? (Binary)
```

### 4-3. 카테고리 기반 그룹핑

Polymarket은 마켓을 다음 카테고리로 분류한다:

| 카테고리  | 예시                 |
| --------- | -------------------- |
| Politics  | 선거, 정책, 외교     |
| Sports    | 경기 결과, 선수 기록 |
| Crypto    | 가격 예측, 규제      |
| Economics | 금리, GDP, 고용      |
| Culture   | 시상식, 엔터테인먼트 |
| Science   | 기후, 우주, 기술     |
| World     | 국제 이벤트          |

## 5. UI/UX 표현 방식

### 5-1. 마켓 카드 표시 정보

- 질문 텍스트
- 현재 YES/NO 가격 (= 확률%)
- 거래량 (Volume)
- 유동성 (Liquidity)
- 마감일 (End Date)
- 카테고리 태그
- 참여자 수

### 5-2. 가격/확률 시각화

- **바이너리**: 단일 확률 바 (YES 63% — NO 37%)
- **카테고리컬(NegRisk)**: 각 옵션별 확률 리스트 (합계 ≈ 100%)
- **시계열 차트**: 시간에 따른 확률 변화 그래프
- **실시간 업데이트**: 거래가 일어날 때마다 가격 반영

### 5-3. 마켓 상태

| 상태     | 설명                 |
| -------- | -------------------- |
| Open     | 거래 가능            |
| Closed   | 거래 마감, 정산 대기 |
| Resolved | 결과 확정, 정산 완료 |
| Disputed | 결과에 이의 제기됨   |

## 6. HotPick 적용 시 참고사항

### Polymarket과 HotPick의 차이점

| 항목          | Polymarket          | HotPick            |
| ------------- | ------------------- | ------------------ |
| 핵심 메커니즘 | 예측 + 금전 베팅    | 의견 투표 (비금전) |
| 결과 도출     | 이벤트 발생 후 정산 | 즉시 결과 확인     |
| 참여 동기     | 수익                | 재미 + 비교 + 공유 |
| 옵션 수       | 2~수십 개           | 2개 (이지선다)     |
| 구조          | 단일 마켓           | 5개 투표 묶음      |

### HotPick에 도입 가능한 Polymarket 요소

1. **카테고리 시스템**: 정치/스포츠/문화 등 카테고리별 분류
2. **실시간 참여율 표시**: Polymarket의 가격 변동처럼 실시간 비율 변화 시각화
3. **이벤트 그룹핑**: 하나의 주제에 여러 관련 투표 묶기 (이미 5개 묶음 구조)
4. **시계열 데이터**: 시간에 따른 투표 비율 변화 차트
5. **마켓 상태 관리**: 진행중/마감/결과확정 상태 구분
6. **방향성 질문**: "O/U" 스타일의 수치 기반 투표 도입 가능성
