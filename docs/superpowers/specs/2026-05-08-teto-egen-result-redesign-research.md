## 배경

Teto-Egen은 H3 검증 사이클 1차 콘텐츠로, 친구들에게 "나는 테토일까 에겐일까?"를 평가받는 게임. 두 결과 화면 모두 리디자인 대상이다.

### 현재 결과 화면 구조

| 화면                            | 컴포넌트                                                                       | 역할                         |
| ------------------------------- | ------------------------------------------------------------------------------ | ---------------------------- |
| `/ask/teto-egen/my`             | [MyResultView.tsx](../../../src/components/features/TetoEgen/MyResultView.tsx) | 본인이 본인의 평가 결과 확인 |
| `/ask/teto-egen/friend/[token]` | [FriendFlow.tsx](../../../src/components/features/TetoEgen/FriendFlow.tsx)     | 친구가 평가 후 결과 확인     |

공통 구성 블록(상→하):

1. `identityHeader` — 타이틀
2. [ResultHeroCard](../../../src/components/features/TetoEgen/ResultHeroCard.tsx) — 적중/의외 뱃지 + "친구들은 OOO님을 테토로 봤어요" + 빅 퍼센트
3. [AnswerPairRow](../../../src/components/features/TetoEgen/AnswerPairRow.tsx) — 좌우 비교 카드 (내 선택 / 친구들 예상)
4. [FriendAnswersCollapse](../../../src/components/features/TetoEgen/FriendAnswersCollapse.tsx) — 토글 펼침 (테토/에겐 진행바 + 친구 칩)
5. `shareArea` — 링크 공유 박스 + CTA (MyResultView만)

### 데이터 자산 (MyTetoEgenLinkResponse)

```
displayName     : 표시명
selfAnswer      : TETO | EGEN          ← 본인 자기평가
selfPrediction  : TETO | EGEN          ← 본인 예상 ("친구들은 나를 X로 볼 것")
friendVotes:
  total, tetoCount, egenCount
  voters[]      : { userId, displayName, vote, votedAt }
```

### 진단 — 왜 "산만하고 임팩트 없음"인가

Bundle 결과 리디자인 스펙([2026-04-24](2026-04-24-bundle-result-redesign-design.md))의 진단을 그대로 적용 가능:

1. **수직 6단 블록 동일 weight** — 시선이 잡히는 곳 없음
2. **숫자 분산** — 빅넘버는 Hero, 인원수는 카피, 분포 막대는 Collapse 안
3. **친구 정보가 토글 뒤** — 80%+ 유저는 펼치지 않음 (가장 흥미로운 데이터가 가려짐)
4. **적중/의외 뱃지가 약함** — variant가 결과의 임팩트를 만들어야 하는데 텍스트 라벨 1줄
5. **"본인 예상(selfPrediction)" 사장** — 가장 재밌을 수 있는 "내 예상 vs 실제" 적중률 angle 누락
6. **공유 가능한 한 컷 부재** — H3 검증 사이클 콘텐츠인데 캡처 한 장으로 단톡방에 던질 게 없음

## 리서치 축 3개

| 축                     | 핵심 질문                                    | 결과물 형태                     |
| ---------------------- | -------------------------------------------- | ------------------------------- |
| **A. 임팩트 카드형**   | "한 장으로 결과를 압도적으로 보여주려면?"    | Spotify Wrapped류 풀블리드 카드 |
| **B. 데이터 시각화형** | "분포·인원·적중률을 한눈에 보여주려면?"      | 폴리마켓·Polis류 인포그래픽     |
| **C. 공유/캐릭터형**   | "캡처해서 인스타·카톡에 올리고 싶게 하려면?" | MBTI·BuzzFeed류 캐릭터 결과     |

## 레퍼런스 후보 15개

각 후보를 7개 체크리스트로 평가한다:

- **F**irst fold composition — 첫 화면 구성
- **H**ero element — 가장 큰 시각 요소
- **I**nformation hierarchy — 1·2·3순위가 시각적으로 구분되나
- **S**hare-readiness — 캡처 한 장이 의미 있나
- **C**opy tone — 데이터 → 한 줄 카피로 어떻게 풀었나
- **M**otion — 정적/모션
- **D**arkmode 적용 가능성 — HotPick 옮길 때 비용

평가는 **● 강함 / ◐ 보통 / ○ 약함** 3단계.

| C    | ● 가장 짧음. 단어 1개.          |
| M    | 회전 애니메이션.                |
| D    | ● 다크 가능.                    |

**HotPick 적용 angle**: 빅 단어 1개 ("테토" 또는 "에겐") 풀스크린으로 진입 모션 → 디테일 펼침. Spotify Wrapped와 결합 가능.

## 결의 1차 추천 — 방향성 시안 3개의 씨앗

리서치 결과를 바탕으로 다음 3개 시안을 다음 단계 방향성 결정에 올린다:

### 시안 ① "선언형 빅카드" (A1 + C4 + C2)

> Spotify Wrapped + MBTI 수식어 + BuzzFeed 공유 CTA

- **First fold**: 풀블리드 그라데이션 + 빅 타이포 "[테토]" + 수식어 1줄 ("친구들이 본 다정한 테토").
- **2 fold**: 친구 N명 중 M명 + 작은 분포 바.
- **3 fold**: 즉시 공유 CTA (큰 버튼).
- **장점**: 캡처 최강, MBTI식 바이럴. selfPrediction 적중 시 "예상도 적중!" 메달 추가 가능.
- **단점**: 데이터 시각화 약함. 친구 개별 정보 보고 싶은 유저는 스크롤 필요.

### 시안 ② "데이터 인사이트형" (A3 + B2 + B3)

> Toss 인사이트 카피 + Polymarket 양분 % + Connections 그리드

- **First fold**: 인사이트 카피 ("친구 10명 중 7명이 테토라고 봤어요") + 빅 % + 작은 양분 바.
- **2 fold**: 친구 dot 그리드 (테토=🔴, 에겐=🔵). selfAnswer 강조.
- **3 fold**: 시간축 voter 리스트 (votedAt 활용).
- **장점**: 모든 데이터가 한 화면에 노출. 정보 충실도 높음.
- **단점**: 캡처 한 장이 약함. 임팩트보다 분석에 가까움.

### 시안 ③ "공유 카드 + 디테일 펼침" (A1 + C1 + B5)

> 풀블리드 캐릭터 카드 + 단톡방용 emoji 그리드 텍스트 + 디테일 펼침

- **First fold**: 캐릭터 카드 (TETO/EGEN 컬러 토템 + 별명).
- **공유 영역**: 카톡에 직접 복붙할 수 있는 "테토에겐 위크 #3 👤 7/10" 형태 텍스트 + 캡처 카드 다운로드.
- **디테일**: AnswerPairRow + Collapse 유지하되 펼침을 기본값으로.
- **장점**: 바이럴 채널 다중 (캡처 + 텍스트). 캐릭터로 정체성 강화.
- **단점**: 캐릭터 자산(일러스트 또는 컬러 토템) 디자인 공수.

## 참고 — 공통 적용 원칙 (Bundle 결과 스펙에서 차용)

- **"나" 우선**: 친구 정보보다 본인 정체성을 first fold에 배치.
- **선언형 카피**: 데이터를 1문장 정체성 카피로 변환 ("친구들이 본 OOO님은 테토예요").

- **selfPrediction 활성화**: "예상 vs 실제" angle을 메인 narrative로 포함 검토.
