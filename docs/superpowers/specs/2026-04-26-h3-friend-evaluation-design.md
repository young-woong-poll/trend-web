# H3 친구 평가 — "내가보는나 / 남이보는나" 디자인 스펙

자기 평가, 자기가 예상한 친구 시선, 실제 친구 시선의 3축 간극을 한 화면에서 적중·빗나감 한 단어로 본다. 1차 검증 콘텐츠는 테토/에겐.

## 배경

전략 문서 [2026-04-25-h3-friend-evaluation.md](../../strategy/2026-04-25-h3-friend-evaluation.md)에서 확정된 가설 — **"핫한 주제(공유 동기) × H3 구조(평가 행위) = 곱셈 관계"** — 의 첫 검증 사이클.

핵심 설계 제약 (전략에서 내려온 것):

- **출시일 2026-05-13**, FE 웅일 단독 작업, 디자인은 결의 본 스펙으로 종결.
- **"심플 + 한 번에 알 수 있게"** — UX 1순위 원칙. "이거 어떻게 하는거야?" 한 번이라도 들면 실패.
- **토스 톤** — 큰 숫자 1개 + 한 줄 카피 + 액션 1개. 부가 정보는 펼침으로.
- BE 변경 최소화. 카카오 로그인 재사용. 단 카운트 API + 1주제 1링크 정책 BE 작업 추가됨.
- 폐기 가능한 하드코딩. `/ask/<topic>/` 네임스페이스로 격리.

본 스펙은 웅일이 Figma에 작성한 와이어프레임([파일](https://www.figma.com/design/yuck9d6TUMp7TM7pEnJbII/Hotpick-%EB%94%94%EC%9E%90%EC%9D%B8?node-id=590-848))을 기준으로 한다.

## 레퍼런스 & 영감

### 토스의 "큰 숫자 한 개 + 한 줄 카피"

- 출처: [design-inspirations.md#토스](../../../.claude/skills/hp-designer/references/design-inspirations.md)
- 해당 패턴: 결과 화면에 가장 큰 시각으로 숫자 1개. 그 위 한 줄 카피로 의미 전달. 부가 정보는 다 아래로.
- HotPick 맞춤 이유: 결과 화면이 정보 밀도 높아질 위험 (자기 평가 + 자기 예상 + 친구 답변 N건). 토스 위계 적용 시 첫 진입에 "62% 테토" 한 숫자만 보이고, 친구 명단은 펼침으로. 캡처 시에도 한 화면에 의미 전달 가능.

### Beli의 친구 단위 입력 환원

- 출처: [design-inspirations.md#Beli](../../../.claude/skills/hp-designer/references/design-inspirations.md)
- 해당 패턴: 친구가 평가에 참여하는 행위 자체가 본인 결과를 만든다.
- HotPick 맞춤 이유: H3 구조의 핵심. 다만 Beli의 "랭킹" 형태가 아니라 "다수/소수 그룹 분포"로 변형.

### Wordle의 미니멀 캡처 카드 → 캡처 위임으로 단순화

- 결의 v1 결정: 별도 ShareCard 컴포넌트 만들지 않고 결과 화면 자체가 캡처해도 의미 전달되도록 설계. 캡처는 OS 기본 기능 위임.

### 정책 노트 (Figma 스티키)

- **1계정 1링크 (주제별)**: 사용자가 한 주제(`/ask/teto-egen`)에 평생 1개 링크. 다른 주제는 별도 1개. 링크 생성 후 투표·닉네임 등 수정 불가.
- **공유 통해서만 진입**: `/ask/teto-egen/friend/{token}`은 공유 링크로만 도달.
- **테토/에겐만 가능**: 직접 입력 옵션 없음. 욕설·노이즈 차단.
- **다음 버튼 유도**: 친구 평가 마치면 "다음" 버튼으로 자기 평가 자연 진입.

## 방향성 결정 (Step 0)

웅일이 Figma 와이어프레임으로 화면 단위까지 정의. 결과 화면 정보 위계만 결이 3개 방향(답변별 그룹 / 친구별 카드 / 1축 분포) 비교 후 **(a) 답변별 그룹 + Layer 1/2 펼침**으로 합의. 토스 톤 적용 시 Layer 1은 큰 숫자 1개 + 적중/빗나감 카피.

**Mock 사용 여부**: 아니오. Figma 와이어프레임이 1차 모크 역할. 토큰·SCSS는 웅일이 본 스펙 기준 직접 처리.

## UX 체크포인트 통과 기록

- **Q1. 유저 목표 한 문장**:
  - 1차 공유자: "내가 친구들에게 어떻게 보일 거라 생각했는지, 친구들이 실제로 나를 어떻게 봤는지가 적중인지 빗나감인지를 한 화면에서 본다."
  - 2차 공유자: "친구가 어떤 사람인지 내 생각을 던지고, 다른 친구들 생각도 그 자리에서 본 뒤 나도 해본다."
- **Q2. 상태 정의**:
  - **엠프티 (1차 결과 화면, 친구 평가 0건)**: 적중/빗나감 카피 영역에 "아직 친구가 평가하지 않았어요" + 큰 카피 영역에 자기 평가 결과만 표시 + 큰 [링크 복사하기] CTA. 친구 답변 펼침은 숨김.
  - **실패/에러 모달 (Figma 명시 4종)**:
    1. **이미 링크가 존재합니다** (확인/새로고침) — 1차 공유자가 이미 본 주제에 링크 있는데 또 생성 시도.
    2. **이미 참여했습니다** (확인/새로고침) — 2차 공유자가 같은 링크에 재참여 시도.
    3. **자신에게 투표할 수 없습니다** — 1차 공유자가 자기 링크로 친구 평가 진입.
    4. **일시적인 에러가 발생했습니다** (확인/새로고침) — API 일반 실패.
  - **로딩**:
    - 자기 평가 → 결과 화면 진입 시 0.3-0.6초 가벼운 스켈레톤. 결과 카드 페이드인.
    - 1차 재진입 시 자기 평가 카드는 즉시(localStorage 캐시), 친구 답변 영역만 스켈레톤.
  - **오프라인**: 카카오 로그인·평가 제출 시점에서 네트워크 끊김 감지 시 "네트워크가 불안정해요. 연결되면 자동으로 다시 시도합니다" 인라인 배너. 답변은 localStorage 임시 저장.
- **Q3. 대안 경로**:
  - 1차 공유자가 평가 도중 이탈: 헤더 좌측 🔙 (Figma에 명시). 누르면 컨펌 모달 ("나가면 처음부터 해야 해요. 그래도 나갈까요?"). 링크 생성 후 이탈은 자유 — 본인 카카오 로그인이라 `/ask/teto-egen/my`로 재진입 가능.
  - 2차 공유자가 친구 평가 안 하고 닫기: 자유 이탈. 진입 동기는 단톡방 회자로 다시 노출.
  - 비로그인 유저: 모든 진입(1차·2차)에서 카카오 로그인 강제. 로그인 거부 시 메인으로.
  - 1차 공유자가 본인 링크 잃어버린 경우: 카카오 로그인 상태이므로 `/ask/teto-egen` 진입 → 자동으로 `/ask/teto-egen/my`로 리다이렉트 (이미 결과 있음 분기).
- **Q4. 카피**:
  - 랜딩 헤드라인: "당신은 테토인가요? 에겐인가요?"
  - 랜딩 서브카피: "내 생각 ↔ 친구들 생각 맞는지 테스투" (테스투는 Figma 톤 그대로 유지 — 인터넷 용어 차용 의도)
  - 랜딩 카운트: "{N}명 참여" (BE 카운트 API 실시간)
  - 자기 평가 1: "당신은 테토인가요? 에겐인가요?"
  - 자기 평가 2: "친구들도 {답}라고 생각할까요?" → [아니다] [그렇다]
  - 링크 생성 화면: "친구들에게 한 번 물어볼까요?" / "어떤 이름으로 물어볼까요?" / "링크가 생성되면 변경이 어려워요"
  - 링크 생성 결과: "👏 투표 링크가 생성되었어요!" / "친구들에게 공유하고 결과를 확인하세요"
  - 1차 결과 화면 (적중): "👏 적중!" + "친구 N명 중 M명이 당신을 {테토/에겐}으로 봤어요"
  - 1차 결과 화면 (빗나감): "🎯 의외!" + "친구 N명 중 M명이 당신을 {테토/에겐}으로 봤어요"
  - 1차 결과 화면 (엠프티): "아직 친구가 평가하지 않았어요"
  - 친구 평가 진입: "{표시이름}님은 테토인가요? 에겐인가요?" / "답하면 {표시이름}님 + 친구들의 답변이 공개됩니다"
  - 2차 결과 화면 헤더: "{표시이름}님의 선택" / "친구들의 답변"
  - 2차 결과 화면 CTA: "다음" (= 본인 자기 평가 시작)
  - 모든 텍스트 존댓말, 한 줄 이내, 기획자/개발자 언어 0.
- **Q5. 회귀 영향**:
  - **신규 라우트만 추가**, 기존 화면 수정 없음 (`/ask/teto-egen/...` 단일 격리).
  - 카카오 로그인 흐름은 기존 LoginModal 그대로. 단 로그인 후 리다이렉트 처리에 신규 라우트 분기 추가.
  - `/my` 탭 노출 여부는 v1에서 결정 보류 — 본인 링크 접근은 `/ask/teto-egen`이 자동 리다이렉트하므로 별도 진입점 불필요. 검증 통과 후 결정.
  - "테토/에겐" 한국 인터넷 용어 의존 — 다국어 확장 시 재정의 필요. 1차 검증 단계라 수용.

## UI 디자인

### 라우팅 구조

| 경로                            | 역할                                                          | 진입 분기                                                                                     |
| ------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `/ask/teto-egen`                | 랜딩 + 진입 분기                                              | 카카오 로그인 강제. 로그인 후: 결과 있음 → `/my` 자동 리다이렉트 / 결과 없음 → 자기 평가 시작 |
| `/ask/teto-egen/my`             | 1차 공유자 본인 영역 (자기 평가 진행 + 링크 생성 + 결과 확인) | 본인만 접근. 단계는 내부 state로 관리                                                         |
| `/ask/teto-egen/friend/{token}` | 2차 공유자 친구 평가                                          | 카카오 로그인 강제. 본인 토큰이면 모달 차단. 이미 참여면 모달 차단                            |

`{token}` — 1차 공유자 카카오 user id 기반 또는 짧은 별칭. **BE 부담 줄이려면 user id 직접 사용 + 짧은 슬러그 매핑** 권장. 단 user id 노출이 보안상 문제면 별칭만.

### 1차 공유자 화면 흐름 (좌측 그룹, Figma)

#### S0. 랜딩 (`/ask/teto-egen`)

- 헤더: 닫기(✕) 우측 상단
- 제목: "당신은 테토인가요? 에겐인가요?"
- 서브: "내 생각 ↔ 친구들 생각 맞는지 테스투"
- 카운트: "{N}명 참여" (BE 카운트 API)
- 큰 CTA: [시작하기] (`$primary-gradient`)
- **분기 (로그인 후)**:
  - 본인이 이 주제에 링크 있음 → `/ask/teto-egen/my` (결과 화면)으로 자동 이동
  - 없음 → 자기 평가 시작

#### S1. 자기 평가 1 (테토/에겐)

- 헤더: 좌측 🔙 (이전), 우측 ✕ (닫기 + 컨펌)
- 질문: "당신은 테토인가요? 에겐인가요?"
- 두 큰 선택 카드: [테토] [에겐]
- 선택 즉시 다음 단계 자동 전환 (0.2s)

#### S2. 자기 평가 2 (친구 시선 예상)

- 질문: "친구들도 {답}라고 생각할까요?" — `{답}`은 S1 선택값
- 두 카드: [아니다] [그렇다]
- 선택 즉시 다음 단계 자동 전환

#### S3. 이름 입력 + 링크 생성

- 상단 비교 줄: "내 선택 [테토] / 친구들 예상 [에겐]" — 작게, 결과 미리보기. (자기 평가 2의 "그렇다/아니다" UI 답을 selfAnswer 기준으로 TETO/EGEN으로 변환해 표시 — Q4 카피 섹션 참조)
- 헤드라인: "친구들에게 한 번 물어볼까요?"
- 입력 라벨: "어떤 이름으로 물어볼까요?"
- 닉네임 입력 필드: 디폴트 = 카카오 닉네임. 12자 제한.
- 큰 CTA: [링크 생성하기] (`$primary-gradient`)
- 안내 (작게): "링크가 생성되면 변경이 어려워요"
- **에러 분기**:
  - 이미 링크 존재 (BE 응답): 모달 "이미 링크가 존재합니다 / [확인(새로고침)]" → 새로고침 시 `/my` 결과 화면으로
  - API 실패: 모달 "일시적인 에러가 발생했습니다 / [확인(새로고침)]"

#### S4. 링크 생성 직후 ( `/ask/teto-egen/my` )

- 상단 이모지: 👏
- 헤드라인: "투표 링크가 생성되었어요!"
- 서브: "친구들에게 공유하고 결과를 확인하세요"
- 링크 박스: `https://hotpick.votebox.kr/ask/teto-egen/friend/{token}` (읽기 전용)
- 큰 CTA: [링크 복사하기] (카카오 공유 SDK 동시 노출 옵션 — v1은 링크 복사만)
- **친구 평가 들어오면 같은 화면이 결과 모드로 전환** (S5).

#### S5. 1차 결과 화면 (`/ask/teto-egen/my`, 친구 평가 ≥ 1건) — **토스 톤 핵심 화면**

화면 구성 (위 → 아래):

**Layer 1 — 큰 숫자 한 개 + 적중/빗나감 카피**

```
👏  적중!

친구 8명 중 5명이
당신을 테토로 봤어요

       62%
      (테토)
```

- 적중/빗나감 자동 판정 로직: 사용자의 자기 평가(테토/에겐)가 친구 답변 다수파와 일치하면 **적중** + 👏, 불일치면 **의외** + 🎯.
- 큰 숫자: 다수파 비율(예: "62%"). 화면 가장 큰 시각 (`$font-size-48` 이상, 굵게).
- 큰 숫자 아래: 다수파 라벨 작게 (`$font-size-16`, "(테토)").

**Layer 1 보조 — 내 선택 / 친구들 예상 작은 비교 줄**

```
─────────────────────────
내 선택        친구들 예상
[테토]         [에겐]
─────────────────────────
```

- 한 줄, 작게 (`$font-size-14`). 두 칩 형태. 자기 평가 2의 "그렇다/아니다" UI 답을 selfAnswer 기준으로 TETO/EGEN으로 변환해 표시 (selfPrediction은 API 도메인이 TETO/EGEN — "그렇다"는 selfAnswer와 동일, "아니다"는 반대 값).

**Layer 2 — 친구 답변 펼침**

- 기본 접힘 상태: "▼ 친구 8명 답변 보기"
- 펼친 상태:

  ```
  ▲ 친구 8명 답변 닫기

  테토 (5명) ━━━━━━ 62%
  다림  지영  수비  민수  현우

  에겐 (3명) ━━━ 38%
  ```

## 결정 근거 (Why)

1. **`/ask/<topic>/` 네임스페이스 격리**: 향후 다른 핫한 주제 시리즈를 같은 prefix에 추가할 수 있도록. 다단계 검증 설계 (전략 PRD)와 정합. 단 시스템 일반화는 검증 통과 후로 미룸.
2. **1차 진입부터 카카오 로그인 강제**: 1주제 1링크 정책 운영을 위해 카카오 ID 식별 필수. 일관성 (1차/2차 다 강제)이 사용자 모델 단순.
3. **자기 평가 2개 질문**: H3 가설(자기-친구 시선 비교)을 가장 압축된 형태로 검증. 질문 6-8개 안 → 2개 안으로 변경 (마찰 ↓, 출시 속도 ↑, 가설 명확성 ↑).
4. **3축 구조 (자기 / 자기 예상 / 실제 친구)**: Figma에 "내 선택 + 친구들 예상 답변" 컬럼이 명시되어 H3 가설이 3축으로 확장됨. 적중/빗나감 자동 판정으로 토스 톤 한 줄에 압축.
5. **결과 화면 토스 톤 (큰 숫자 1개 + 적중/빗나감 카피)**: 정보 밀도 위험을 위계로 해결. Layer 1은 큰 숫자 + 한 줄 + 작은 비교 줄. 친구 명단은 Layer 2 펼침. 캡처해도 한 화면에 의미 전달.
6. **직접 입력 옵션 삭제** (Figma 정책): 욕설·노이즈가 링크 소유자 곤란하게 함. 테토/에겐 두 가지만.
7. **"주인공에게 보여주기" CTA 없음**: 캡처가 자연스럽고 별도 결과 공유 링크는 BE 부담 추가 + 정책("공유 통해서만 진입") 충돌. 캡처는 OS 기본 위임.
8. **1주제 1링크 (수정 불가)** (Figma 정책): 공유 후 변경 시 혼란. "링크 생성되면 변경이 어려워요" 사전 명시 → 사용자 신중 결정 유도.
9. **NicknameModal 분리 → S3 화면 통합**: 별도 모달 단계가 마찰 추가. Figma 와이어처럼 한 화면에서 이름 + 링크 생성 동시.
10. **GapAxisChart 폐기**: 이산 답변(테토/에겐 2지선다)에 1축 분포 시각이 부적합. 답변별 그룹 + 막대바가 더 직관적.
11. **Canvas 사용 금지**: Phase 1의 OrbitMap이 Canvas였고 보류 브랜치에 격리. 본 사이클은 단순 SVG·div·CSS로 충분.

## BE 추가 작업

**원칙: 기존 bundle BE 재사용 안 함, 신규 도메인으로 완전 분리.**

근거 4가지:

1. **데이터 모델 충돌**: 번들은 N개 질문 묶음 모델, H3는 고정 2+1 질문 단일 주제 모델. 번들 스키마에 끼우면 사용 안 하는 필드 50%.
2. **정책 차이**: H3의 "1주제 1링크 + 변경 불가 + 자기 토큰 차단 + 중복 참여 차단" 정책은 번들에 없음. 같은 테이블에 두면 분기 if문이 코드베이스에 퍼짐.
3. **폐기 가능성**: 본 사이클은 H3 검증용 폐기 가능 하드코딩 (전략 PRD 명시). 실패 시 도메인째 깔끔히 제거 가능해야 함.
4. **BE 동료 작업 명세 단순화**: 신규 테이블 2개 + 엔드포인트 5개로 명세 명확. 끼워 맞추기보다 빠르게 구현·테스트 가능.

웅일과 합의: 1-2일 추가 비용 감수, 별도가 맞다.

**상세 BE 개발요청서**: [docs/api/ask-teto-egen-api-spec.md](../../api/ask-teto-egen-api-spec.md). 본 디자인 스펙의 화면 데이터 요구를 기반으로 작성. BE 동료에게는 그 문서를 1차 전달.

요약:

- **테이블 2개**: `ask_teto_egen_links` (1주제 1링크 unique 제약), `ask_teto_egen_votes` (1링크 1유저 unique 제약)
- **엔드포인트 5개**:
  - `GET  /api/v1/ask/teto-egen/count` — 랜딩 참여자 카운트
  - `POST /api/v1/ask/teto-egen/links` — 본인 링크 생성 (409 if 중복)
  - `GET  /api/v1/ask/teto-egen/links/me` — 본인 링크 + 친구 평가 집계
  - `GET  /api/v1/ask/teto-egen/friend/:token` — 친구 평가 진입 메타 (표시이름·자기답변 숨김)
  - `POST /api/v1/ask/teto-egen/friend/:token/vote` — 친구 평가 제출 (자기 토큰·중복 차단)

검증 통과 시 v2에서 검토할 것들. **현재는 하지 않는다**.
