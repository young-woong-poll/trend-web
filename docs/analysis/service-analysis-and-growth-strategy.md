## 1. 현재 서비스 현황 요약

### 1.1 서비스 정의

**핫픽(HotPick)** — "애매하면? 핫픽"
바이럴 투표 플랫폼. 이지선다 투표를 통해 대중의 취향과 의견을 확인하고, 결과를 공유하여 바이럴을 일으키는 스낵형 콘텐츠 서비스.

- **타겟**: 20-40대 한국 청년, 모바일 우선
- **핵심 루프**: 투표 → 즉시 결과 확인 → 공유 → 친구 유입 → 재투표

### 1.2 구현 완료 기능

| 기능                    | 상태    | 설명                                                                 |
| ----------------------- | ------- | -------------------------------------------------------------------- |
| SINGLE 핫픽 (단일 투표) | ✅ 완료 | 메인 피드 인라인 투표 + 상세페이지                                   |
| 메인 피드               | ✅ 완료 | 무한스크롤, 카테고리 필터, 정렬                                      |
| 투표 애니메이션         | ✅ 완료 | Framer Motion 3-phase (700ms)                                        |
| 댓글 시스템             | ✅ 완료 | 작성/수정/삭제, 좋아요, 정렬                                         |
| 공유하기                | ✅ 완료 | 클립보드 복사 + 동적 OG 이미지                                       |
| 카테고리 시스템         | ✅ 완료 | 7개 카테고리 필터 (연애, 재테크, 직장, 트렌드, 생활, 결혼, 인간관계) |
| Admin 관리자            | ✅ 완료 | 핫픽 CRUD, 카테고리 관리, 이미지 업로드                              |
| 동적 OG 이미지          | ✅ 완료 | 핫픽별 Edge Runtime OG 이미지 생성                                   |
| SEO                     | ✅ 완료 | 동적 메타데이터, 사이트맵, 네이버 웹마스터                           |
| GA4 추적                | ✅ 완료 | 페이지뷰 기본 추적                                                   |
| PWA 매니페스트          | ✅ 완료 | standalone, 다크 테마                                                |

## 2. 장점 분석

### 2.1 ✅ 극도로 낮은 참여 장벽

**핵심 강점.** 로그인 없이 한 번의 탭으로 투표 가능. UUID 기반 익명 식별 방식으로 "가입 피로"를 완전히 제거했다.

- 비교: Twitter 폴은 로그인 필수, Polymarket은 지갑 연결 필요
- HotPick은 페이지 접속 → 탭 1회 → 즉시 결과. **최소 마찰 설계**
- 댓글도 닉네임+비밀번호만으로 작성 가능 (비로그인)

> Forrester 2024 리서치: 투표/설문 참여에서 마찰을 한 단계 줄일 때마다 전환율이 2-3배 향상

### 2.2 ✅ 즉각적 그라티피케이션 (즉시 보상)

투표 즉시 결과를 볼 수 있는 설계는 도파민 루프를 만든다:

1. **궁금증** ("다른 사람들은 뭘 골랐을까?")
2. **선택** (탭 1회)
3. **보상** (즉시 결과 + "나는 62% 다수파" 또는 "나는 18% 소수파")
4. **공유 욕구** ("이거 봐!")

3-phase 애니메이션(700ms)이 이 루프를 더 매력적으로 만든다.

### 2.3 ✅ 콘텐츠-제품 일체형 구조

각 투표가 곧 독립적인 콘텐츠이며, 공유 가능한 단위이다:

- 동적 OG 이미지가 자동 생성되어 카카오톡/SNS에서 프리뷰 카드가 표시됨
- `/hotpick/{slug}` 고유 URL이 SEO에 유리
- 각 투표가 독립적인 바이럴 포인트로 기능

### 2.4 ✅ 스낵형 소비에 최적화된 UX

- 무한스크롤 + 카드형 UI → 틱톡/인스타 스토리와 유사한 소비 패턴
- 한 투표에 3초 소요 → 출퇴근, 화장실, 줄 서기 등 자투리 시간에 딱 맞음
- "짧게 즐기는 도파민 간식"이라는 슬로건과 제품이 일치

### 2.5 ✅ 기술적 견고함

- React 19 + Next.js 16: 최신 기술 스택으로 장기 유지보수에 유리
- Orval로 API 타입 자동 생성: BE-FE 불일치 최소화
- Playwright E2E 테스트: 핵심 플로우 자동 검증
- 옵티미스틱 업데이트 + 롤백: 투표 UX의 반응 속도 극대화
- ISR(60초): SEO 크롤링과 실시간성의 균형

### 2.6 ✅ 20-40대 청년 타겟에 맞는 브랜딩

- 다크 테마(#121212)는 젊은 세대에 친화적
- 그라데이션 포인트 컬러(#ff00ff → #ff4500)는 게이밍/테크 바이브
- 간결한 카피와 해시태그 활용 (#공감능력200%, #확고한취향)
- FOMO 자극 전략 ("이거 안 하면 이번 주 대화에 못 낌")

## 3. 단점 및 한계 분석

### 3.1 ❌ 바이럴 루프의 불완전성 (가장 큰 문제)

현재 공유 기능은 **클립보드 복사뿐**이다. 바이럴 루프가 자동으로 돌지 않는다.

| 바이럴 루프 단계    | 현재 상태 | 문제                                          |
| ------------------- | --------- | --------------------------------------------- |
| 1. 투표 참여        | ✅ 작동   | —                                             |
| 2. 결과 확인        | ✅ 작동   | —                                             |
| 3. 공유 동기 발생   | ⚠️ 약함   | "내 결과"를 자랑할 포맷이 없음                |
| 4. 공유 실행        | ⚠️ 제한적 | 클립보드 복사만 지원, Web Share API 미사용    |
| 5. 친구가 링크 클릭 | ⚠️ 약함   | OG 프리뷰는 있지만, "나도 해보자" 동기가 약함 |
| 6. 친구가 투표      | ✅ 작동   | —                                             |
| 7. 친구가 다시 공유 | ❌ 끊김   | 공유 후 "결과 비교" 등의 재순환 메커니즘 없음 |

**K-factor(바이럴 계수) 추정: 0.2-0.3** (자기증식 임계값 1.0에 크게 미달)

> Polymarket은 Twitter 링크 프리뷰에 실시간 결과를 표시하여, 공유 자체가 광고 역할을 하게 만들었다. HotPick도 결과가 담긴 공유 카드가 필요하다.

### 3.2 ❌ 재방문 동기의 부재

사용자가 한 번 방문 후 다시 돌아올 이유가 없다:

| 재방문 메커니즘      | 현재                | 효과 |
| -------------------- | ------------------- | ---- |
| 푸시 알림            | ❌ 없음             | —    |
| 이메일 뉴스레터      | ❌ 없음             | —    |
| 스트릭/연속 참여     | ❌ 없음             | —    |
| 마감 긴급감          | ❌ 없음 (상시 투표) | —    |
| 콘텐츠 업데이트 알림 | ❌ 없음             | —    |
| 예측 결과 확인       | ❌ 없음             | —    |

> Duolingo는 스트릭 시스템 도입 후 DAU/MAU 비율을 37%까지 끌어올렸다. 7일 이상 스트릭 유지 시 일일 재참여율이 2.3배 상승.

### 3.3 ❌ BUNDLE 핫픽 미완성 → 콘텐츠 다양성 부족

바이럴 엔진으로 기획된 "5개 투표 묶음 → 성향 유형 분류"가 아직 작동하지 않는다:

- 결과 페이지(유형 카드, 대중성 지수)가 스텁 상태
- BUNDLE 투표 시 "준비 중" 에러
- 6가지 유형 분류가 미구현

SINGLE의 핵심 차별점("대중의 답을 탭 한 번에 숫자로" — 커뮤니티 댓글 3~5개가 아닌 수천 명의 정량적 데이터)은 유효하지만, BUNDLE 완성 시 바이럴 루프(유형 결과 카드 공유 → 신규 유저 유입)를 가동할 수 있어 성장 가속화에 중요하다.

### 3.4 ❌ 콘텐츠 공급 병목

현재 콘텐츠는 **100% 관리자가 수동 생성**:

- 투표 생성 → 이미지 준비 → Admin에서 등록 → 발행
- 유저 생성 콘텐츠(UGC) 없음
- 자동화/AI 기반 콘텐츠 생성 없음
- 시의성 있는 이슈에 빠르게 대응하기 어려움

> 콘텐츠 공급이 서비스 성장의 병목이 된다. 일일 10-20개의 투표 콘텐츠를 지속 공급해야 DAU를 유지할 수 있다.

### 3.5 ❌ 사용자 식별/상태 영속성 취약

UUID(localStorage) 기반 식별의 한계:

- 브라우저 데이터 삭제 시 투표 이력 소실
- 기기 간 동기화 불가
- 스트릭, 배지 등 누적 게임화 요소 구현이 어려움
- 푸시 알림을 위한 사용자 도달 수단 없음

### 3.6 ❌ 사회적 상호작용 부족

투표는 본질적으로 사회적 행위이지만, 현재 사용자 간 상호작용이 제한적:

- 댓글은 있지만, "친구와 비교" 기능 없음
- "나와 다른 선택을 한 사람들의 의견" 하이라이트 없음
- 결과에 대한 토론/반응 메커니즘 약함
- 팔로우, 친구, 그룹 등 소셜 그래프 없음

### 3.7 ❌ 유입 채널의 부재

현재 신규 유저 유입 경로가 거의 없다:

- 오가닉 검색(SEO): 투표 콘텐츠의 검색 노출이 제한적
- SNS 공유: 바이럴 루프가 약해 자기증식 미발생
- 앱스토어: 네이티브 앱 없음
- 커뮤니티: 외부 커뮤니티 연동 없음
- 광고: 집행 이력 없음(추정)

### 3.8 ⚠️ 분석/측정 인프라 부족

- GA4 페이지뷰만 추적, 커스텀 이벤트 없음
- 투표 전환율, 공유율, 댓글 작성률 등 핵심 지표 미추적
- A/B 테스트 인프라 없음
- Sentry 등 에러 모니터링 없음

## 4. 성장을 위한 핵심 전략 프레임워크

### 4.1 AARRR 프레임워크로 본 현재 상태

```
Acquisition (유입)    ⬛⬜⬜⬜⬜  20%  — SEO/OG만 존재, 적극적 유입 채널 없음
Activation (활성화)   ⬛⬛⬛⬛⬜  80%  — 첫 투표까지의 마찰 극도로 낮음
Retention (유지)      ⬛⬜⬜⬜⬜  10%  — 재방문 동기 거의 없음
Referral (추천)       ⬛⬛⬜⬜⬜  30%  — 공유 가능하나 루프 미완성
Revenue (수익)        ⬜⬜⬜⬜⬜   0%  — 수익화 없음
```

### 4.2 우선순위: Retention → Referral → Acquisition

현재 Activation은 이미 훌륭하다. **가장 시급한 것은 Retention(재방문)과 Referral(바이럴)이다.**

물이 새는 양동이에 물을 부어봐야 소용없다. 유입을 늘리기 전에 재방문/공유 메커니즘을 먼저 완성해야 한다.

### 4.3 핵심 지표 목표

| 지표                       | 현재(추정) | 6개월 목표 | 12개월 목표 |
| -------------------------- | ---------- | ---------- | ----------- |
| DAU                        | 50-200     | 2,000      | 10,000      |
| DAU/MAU 비율               | 5-10%      | 20%        | 30%         |
| 공유율 (투표 후 공유 비율) | 1-2%       | 8%         | 15%         |
| K-factor                   | 0.2        | 0.7        | 1.2+        |
| 투표당 평균 댓글 수        | 0.5        | 3          | 10          |
| 평균 세션 시간             | 1분        | 3분        | 5분+        |

## 5. 구체적 기획 아이디어 — 즉시 도입 (1-4주)

### 5.1 💡 결과 공유 카드 (Share Card) — 바이럴 루프 강화

**문제**: 현재 공유는 URL 복사뿐. 공유받은 사람이 "나도 해보고 싶다"는 동기가 약하다.

**제안**: 투표 후 개인화된 "결과 공유 카드"를 자동 생성하여, SNS에 바로 올릴 수 있게 한다.

**공유 카드 디자인:**

```
┌─────────────────────────────────────┐
│  🔥 HotPick                         │
│                                     │
```

### 5.2 💡 Web Share API 도입 — 공유 마찰 제거

**문제**: 현재 클립보드 복사만 지원 → 카카오톡에 붙여넣기까지 3단계 필요

**제안**: `navigator.share()` 도입으로 네이티브 공유 시트 활용

```typescript
async function handleShare(url: string, title: string) {
  if (navigator.share) {
    await navigator.share({
      title: `${title} - HotPick`,
      text: '너는 어떻게 생각해? 🔥',
      url,
    });
  } else {
    await navigator.clipboard.writeText(url);
    toast('링크가 복사되었습니다');
  }
}
```

**효과:**

- iOS/Android 모두 네이티브 공유 시트 → 카카오톡, 문자, 인스타 등 원탭 공유
- 공유 실행률 2-3배 향상 (Hubspot 2024 데이터)

```
5. 같은 5개 투표 진행
6. 결과 페이지: A의 선택 vs B의 선택 비교

[대결 결과]
┌─────────────────────────────────────┐
│  ⚔️ 대결 결과                        │
│                                     │
│  나 (명예 한국인) vs 친구 (외계인)    │
│  대중성: 78%     vs     22%         │
│                                     │
│  일치한 선택: 2/5 (40%)             │
│  정반대 선택: 3/5 (60%)             │
│                                     │
│  "취향이 완전 다르네!" 🔥            │
│                                     │
│  [결과 공유하기]  [다른 친구 도전]    │
└─────────────────────────────────────┘
```

**바이럴 효과:**

- 대결 링크 공유 = 자연스러운 친구 초대
- 결과 비교 공유 = 2차 바이럴
- "취향이 같다/다르다" → SNS 대화 소재

### 7.3 💡 AI 기반 콘텐츠 자동 생성 — 콘텐츠 공급 혁신

**문제**: 수동 콘텐츠 생성이 서비스 성장의 최대 병목.

**제안**: 트렌드 뉴스/SNS 데이터를 기반으로 AI가 투표 콘텐츠를 자동 제안

**파이프라인:**

```
[데이터 소스]
- Naver 실검/트렌딩
- Twitter/X 트렌딩 토픽 (한국)
- 네이버 뉴스 헤드라인
- 커뮤니티 인기글 (디시, 에펨, 루리웹)

     ↓

[AI 투표 생성기]
- GPT-4/Claude API로 이슈 → A vs B 질문 변환
- 예: "손흥민 리그 이적설" → "손흥민, 새 팀으로 어디가 좋을까? EPL 잔류 vs 사우디 이적"
- 이미지: 관련 Unsplash/자동 생성 or 텍스트 투표 형태

     ↓

[관리자 큐레이션]
- AI가 생성한 투표 초안 목록을 Admin에서 확인
- 승인/수정/삭제 후 발행
- 하루 20-30개 초안 → 관리자가 10개 선별 발행
```

**효과:**

- 콘텐츠 생성 시간 90% 절감
- 시의성 있는 이슈에 실시간 대응 가능
- 관리자 1명으로도 일일 10-20개 콘텐츠 발행 가능

### 7.5 💡 커뮤니티 시딩 전략 — 유입 채널 확보

**문제**: 외부 유입 채널이 없다.

**제안**: 타겟 커뮤니티(20-40대 청년)에서 자연스러운 노출

**타겟 커뮤니티:**

| 커뮤니티     | 특성                    | 접근 방법                      |
| ------------ | ----------------------- | ------------------------------ |
| 에펨코리아   | 직장인 다수, MAU 111M   | 투표 결과 이미지 시딩          |
| 루리웹       | 게임/IT 커뮤니티        | 게임/IT 관련 투표 이미지 시딩  |
| MLB파크      | 야구 팬                 | 스포츠 예측 투표 이미지 시딩   |
| 디시인사이드 | 최대 커뮤니티, MAU 212M | 갤러리별 맞춤 투표 이미지 시딩 |
| 클리앙       | IT/테크                 | 테크 관련 투표 이미지 시딩     |
| 블라인드     | 직장인                  | 직장 관련 투표 이미지 시딩     |

**시딩 전략 (기획서 원칙 준수: 직접 링크 금지):**

1. 각 커뮤니티에서 자주 논쟁이 되는 주제를 투표로 만듦
2. 투표 결과 캡처 이미지를 "순수 참여 후기"처럼 업로드 (이미지 안 워터마크로 유입 유도)
3. "이거 결과가 의외인데?" 식의 호기심 유발 제목
4. 워터마크 본 사람이 "핫픽" 검색 → 네이버 블로그/SEO로 랜딩

**포스트 예시 (에펨코리아):**

```
[제목] 짜장면 vs 짬뽕, 1,000명 투표 결과가 의외임.jpg

[결과 캡처 이미지 — 워터마크에 "핫픽" 로고 포함]

짬뽕 선택한 사람이 72%ㄷㄷ
나만 짜장인건가...
```

> ⚠️ 커뮤니티 시딩 시 직접 링크를 절대 사용하지 않음. 홍보글로 신고당하고 계정 밴 위험. 이미지 워터마크 → 검색 유입 경로를 활용.
