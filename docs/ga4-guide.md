# GA4 번들 퍼널 분석 가이드

> HotPick 번들 기능의 유저 진입/이탈/전환 분석을 위한 실전 가이드.
> GA4 속성: `G-CBJFPV9C95`

---

## 1. 심어둔 커스텀 이벤트 전체 목록

### 번들 풀기 퍼널

| #   | 이벤트명             | 파라미터                             | 설명                    |
| --- | -------------------- | ------------------------------------ | ----------------------- |
| 1   | `bundle_view`        | `slug`, `entry_point`                | 번들 인트로 페이지 조회 |
| 2   | `bundle_start`       | `slug`                               | "시작하기" 버튼 클릭    |
| 3   | `bundle_answer`      | `slug`, `question_index`, `selected` | 질문 답변 (0부터 시작)  |
| 4   | `bundle_complete`    | `slug`, `question_count`             | 전체 답변 제출 완료     |
| 5   | `bundle_result_view` | `slug`                               | 내 결과 페이지 조회     |

### 비교 퍼널

| #   | 이벤트명          | 파라미터                                   | 설명                                |
| --- | ----------------- | ------------------------------------------ | ----------------------------------- |
| 6   | `compare_create`  | `slug`, `compare_type`, `source`           | 비교 링크 생성 성공                 |
| 7   | `compare_share`   | `slug`, `method`, `compare_type`, `source` | 공유 (kakao/copy)                   |
| 8   | `compare_landing` | `bundle_slug`, `compare_type`              | 비교 링크 랜딩 페이지 (수신자 기준) |
| 9   | `compare_result`  | `bundle_slug`                              | 1:1 비교 결과 조회                  |
| 10  | `group_result`    | `bundle_slug`, `member_count`              | 그룹 비교 결과 조회                 |

### 파라미터 값 참고

| 파라미터         | 가능한 값                                         | 의미                          |
| ---------------- | ------------------------------------------------- | ----------------------------- |
| `entry_point`    | `direct`, `compare_link`                          | 직접 진입 vs 비교 링크로 진입 |
| `compare_type`   | `ONE_TO_ONE`, `GROUP`                             | 1:1 vs 그룹                   |
| `source`         | `bundle_result`, `compare_result`, `group_result` | 어디서 링크를 생성했는지      |
| `method`         | `kakao`, `copy`                                   | 공유 방법                     |
| `question_index` | 0, 1, 2, 3, 4                                     | 몇 번째 질문 (0부터)          |
| `selected`       | `A`, `B`                                          | 어떤 선택지                   |

### User ID

로그인 유저는 서버 DB의 `user.id`가 GA4 User ID로 자동 설정됩니다.
GA4에서 "유저 탐색"이나 "코호트" 분석 시 동일 유저의 세션을 합산할 수 있습니다.

## 2. GA4에서 이벤트 확인하기

### 2-1. 실시간 이벤트 확인 (배포 직후 테스트)

1. [GA4 콘솔](https://analytics.google.com/) 접속
2. 좌측 메뉴 > **보고서** > **실시간**
3. "이벤트 수(이벤트 이름별)" 카드에서 `bundle_view`, `bundle_start` 등이 보이면 정상
4. 이벤트 이름 클릭 → 파라미터 값(slug, source 등) 확인 가능

> 이벤트가 안 보이면 **30초~2분** 대기. GA4 실시간은 약간의 딜레이가 있음.

### 2-2. 커스텀 이벤트 등록 (최초 1회)

GA4는 자동 수집 이벤트 외에 커스텀 이벤트의 파라미터를 보려면 **커스텀 정의**에 등록해야 합니다.

1. GA4 콘솔 > 좌측 하단 **관리** (톱니바퀴)
2. **데이터 표시** > **맞춤 정의**
3. **맞춤 측정기준 만들기** 클릭
4. 아래 항목들을 하나씩 등록:

| 측정기준 이름    | 이벤트 매개변수  | 범위   |
| ---------------- | ---------------- | ------ |
| 번들 slug        | `slug`           | 이벤트 |
| 진입점           | `entry_point`    | 이벤트 |
| 비교 타입        | `compare_type`   | 이벤트 |
| 출처             | `source`         | 이벤트 |
| 공유 방법        | `method`         | 이벤트 |
| 질문 번호        | `question_index` | 이벤트 |
| 선택지           | `selected`       | 이벤트 |
| 번들 slug (비교) | `bundle_slug`    | 이벤트 |

5. **맞춤 측정항목 만들기** 클릭:

| 측정항목 이름 | 이벤트 매개변수  | 범위   | 측정 단위 |
| ------------- | ---------------- | ------ | --------- |
| 질문 수       | `question_count` | 이벤트 | 표준      |
| 그룹 멤버 수  | `member_count`   | 이벤트 | 표준      |

> 등록 후 데이터 반영까지 **24~48시간** 소요. 실시간 보고서에서는 바로 파라미터 확인 가능.

## 3. 핵심 보고서 만들기

### 3-1. 번들 퍼널 분석 (어디서 이탈하나?)

**목적:** 인트로 → 시작 → 완료 → 결과 → 비교 생성 각 단계 전환율 확인

1. GA4 콘솔 > **탐색** > **새 탐색 만들기**
2. **기법**: `퍼널 탐색` 선택
3. **단계 설정**:

| 단계 | 이벤트               |
| ---- | -------------------- |
| 1    | `bundle_view`        |
| 2    | `bundle_start`       |
| 3    | `bundle_complete`    |
| 4    | `bundle_result_view` |
| 5    | `compare_create`     |
| 6    | `compare_share`      |

4. **설정**:
   - "세그먼트 비교" 에서 기기별/기간별 비교 가능
   - "개방형 퍼널" 체크: 중간 진입 유저도 포함 (비교 링크로 바로 들어온 유저)
   - "폐쇄형 퍼널" 체크: 1단계부터 순서대로 거친 유저만 (순수 전환율)

5. **읽는 법**:
   - 각 단계 사이의 % = 전환율
   - 예: bundle_view(1000) → bundle_start(600) = **60% 시작 전환율**
   - 큰 이탈이 있는 구간 = 부스팅 필요 포인트

### 3-2. 질문별 이탈 분석 (몇 번째 질문에서 나가나?)

**목적:** 5개 질문 중 어디서 이탈률이 높은지 확인

1. GA4 콘솔 > **탐색** > **자유형식**
2. **행**: `question_index` (맞춤 측정기준)
3. **값**: `이벤트 수`
4. **필터**: 이벤트 이름 = `bundle_answer`

이렇게 하면:

```
question_index 0: 580회
question_index 1: 560회
question_index 2: 520회
question_index 3: 490회
question_index 4: 480회
```

급격히 떨어지는 구간이 있으면 해당 질문이 이탈 유발.

### 3-3. 비교 링크 전환 분석 (공유가 실제 유입으로 이어지나?)

**목적:** 링크 생성 → 공유 → 상대방 진입 → 결과 확인 전환 추적

1. GA4 콘솔 > **탐색** > **퍼널 탐색**
2. **단계**:

| 단계 | 이벤트                               |
| ---- | ------------------------------------ |
| 1    | `compare_create`                     |
| 2    | `compare_share`                      |
| 3    | `compare_landing`                    |
| 4    | `compare_result` 또는 `group_result` |

> 주의: 3~4단계는 **다른 유저**가 수행함. GA4 퍼널에서는 같은 유저 기준이므로,
> 이 퍼널은 "전체 이벤트 수 기준"으로 봐야 합니다.
> 정확한 링크→유입 전환은 아래 3-5 방식으로 확인.

### 3-4. 비교 링크 출처별 생성량 (어디서 많이 만드나?)

**목적:** 번들결과 vs 1:1결과 vs 그룹결과 중 어디서 비교 링크가 많이 만들어지는지

1. GA4 콘솔 > **탐색** > **자유형식**
2. **행**: `source` (맞춤 측정기준)
3. **열**: `compare_type` (맞춤 측정기준)
4. **값**: `이벤트 수`
5. **필터**: 이벤트 이름 = `compare_create`

결과 예시:

| source         | ONE_TO_ONE | GROUP |
| -------------- | ---------- | ----- |
| bundle_result  | 120        | 45    |
| compare_result | 30         | 10    |
| group_result   | 15         | 25    |

→ 번들 결과에서 가장 많이 생성되면 정상, 비교 결과에서도 활발하면 바이럴 루프가 잘 도는 것.

### 3-5. 공유→유입 전환 (링크 공유가 실제 방문으로 이어지나?)

**목적:** compare_share 대비 compare_landing 비율 확인

1. GA4 콘솔 > **보고서** > **참여도** > **이벤트**
2. `compare_share` 이벤트 수와 `compare_landing` 이벤트 수를 비교

```
compare_share: 200회 (링크 공유)
compare_landing: 80회 (실제 유입)
→ 공유→유입 전환율: 40%
```

전환율이 낮으면:

- 카카오 메시지 미리보기가 매력적이지 않음
- 링크를 복사만 하고 실제 전달을 안 함
- 전달했지만 수신자가 클릭하지 않음

### 3-6. 번들별 성과 비교

**목적:** 어떤 번들(slug)이 가장 인기 있고 전환이 좋은지

1. GA4 콘솔 > **탐색** > **자유형식**
2. **행**: `slug` (맞춤 측정기준)
3. **값**: `이벤트 수`
4. **필터**: 이벤트 이름에 `bundle_view`, `bundle_complete`, `compare_create` 각각 필터

결과를 엑셀에 정리하면:

| slug            | view | complete | 완료율 | compare_create | 비교 전환율 |
| --------------- | ---- | -------- | ------ | -------------- | ----------- |
| love-values     | 1000 | 600      | 60%    | 200            | 33%         |
| marriage-values | 500  | 400      | 80%    | 180            | 45%         |

→ 결혼 번들이 완료율과 비교 전환율 모두 높으면 타겟 콘텐츠 확대.

## 4. 주기적으로 확인할 지표

### 매일 확인 (실시간 보고서)

- 오늘 `bundle_view` 수 → 유입량
- 오늘 `bundle_complete` 수 → 완료 수
- 오늘 `compare_create` 수 → 바이럴 활동

### 주간 확인 (탐색 보고서)

| 지표        | 계산                                              | 목표  |
| ----------- | ------------------------------------------------- | ----- |
| 시작 전환율 | bundle_start / bundle_view                        | > 50% |
| 완료율      | bundle_complete / bundle_start                    | > 70% |
| 비교 생성율 | compare_create / bundle_result_view               | > 20% |
| 공유율      | compare_share / compare_create                    | > 60% |
| 유입 전환율 | compare_landing / compare_share                   | > 30% |
| 결과 도달율 | (compare_result + group_result) / compare_landing | > 50% |

### 보고 시 주의 포인트

- **시작 전환율이 낮으면**: 인트로 페이지 CTA/설명 개선
- **완료율이 낮으면**: 질문별 이탈 분석 (3-2) → 문제 질문 교체/수정
- **비교 생성율이 낮으면**: 결과 페이지 CTA 강화, 비교의 재미 어필
- **공유율이 낮으면**: 공유 UI 개선, 카카오 메시지 프리뷰 매력도 향상
- **유입 전환율이 낮으면**: 카카오 미리보기/링크 메시지 개선

## 5. 고급: User ID 활용

### 5-1. User Explorer (개별 유저 여정 추적)

1. GA4 콘솔 > **탐색** > **사용자 탐색**
2. 특정 유저 클릭 → 해당 유저의 이벤트 타임라인을 순서대로 확인
3. "이 유저는 bundle_view → bundle_start → bundle_answer(0,1,2) → 이탈" 같은 개별 여정 확인

> User ID가 설정되어 있으므로 모바일/PC 세션이 합산됩니다.

### 5-2. 세그먼트 만들기

자주 쓰는 세그먼트 예시:

- **번들 완료 유저**: `bundle_complete` 이벤트 발생
- **비교 활성 유저**: `compare_create` 이벤트 발생
- **이탈 유저**: `bundle_start` 있으나 `bundle_complete` 없음

이 세그먼트를 퍼널이나 자유형식에 적용하면 그룹 간 비교 가능.

## 6. DebugView로 테스트하기

배포 전에 이벤트가 제대로 발생하는지 확인하는 방법:

1. Chrome에서 [GA4 DebugView 확장 프로그램](https://chrome.google.com/webstore/detail/google-analytics-debugger/jnkmfdileelhofjcijamephohjechhna) 설치
2. 확장 프로그램 활성화 (아이콘 클릭 → ON)
3. 사이트 접속 후 번들 플로우 진행
4. GA4 콘솔 > **관리** > **DebugView**
5. 실시간으로 이벤트가 하나씩 올라오는 것 확인
6. 각 이벤트 클릭 → 파라미터 값 정확한지 검증

> DebugView는 디버그 모드에서만 작동. 프로덕션에서는 실시간 보고서를 사용하세요.

## 7. 이벤트가 안 보일 때 체크리스트

1. **AdBlocker 꺼져있는지** — uBlock 등이 gtag.js를 차단할 수 있음
2. **GA4 속성 ID 맞는지** — `G-CBJFPV9C95` 확인
3. **이벤트 이름 오타** — GA4 > 이벤트에서 이름 확인
4. **맞춤 정의 등록했는지** — 파라미터가 보고서에 안 뜨면 2-2 단계 확인
5. **24~48시간 대기** — 맞춤 정의 등록 후 데이터 반영 시간 필요
6. **실시간에서 먼저 확인** — 실시간 보고서는 즉시 반영
